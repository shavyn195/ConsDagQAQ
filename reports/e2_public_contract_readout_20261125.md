# E2 完整公开输入单体对照

日期：2026-11-25（北京时间）。这是已完成的探索性公平输入修正版；不替代三种训练 seed 的架构检验。

## 实验与复核

单体 Qwen3-1.7B LoRA、seed 42、bf16，在 v5 的 12,000 条训练行上训练 9,000 次 optimizer update。它直接从用户请求生成工具计划。对照管线使用相同 seed42 的冻结编译器预测约束，再由符号规划器生成计划。输入数据、切分、用户 query 和执行评分器对齐；单体获得公开策略、工具信息和完整任务结构。训练目标不同：单体学习 witness/default plan，编译器学习 typed constraints，且编译器的下游规划器是确定性算法。故这是对当前两套端到端方案的比较，不是隔离某一架构因素的实验。

独立审计脚本在 CPU 上重新解析所有原始计划，复用冻结执行检查器，验证所有数据哈希、训练来源哈希、每条记录 ID、E/I/N 组完整性、保存的逐条评分、配对 bootstrap 结果和 token 账。四个切分全部逐条一致，配对结果和原汇总完全复现；没有重训、额外 API 调用或改写模型产物。审计产物为 `outputs/submission/followup_20261125/e2_public_contract_independent_audit_v2.json`。

## 受约束执行结果

主指标为受约束 E/I 行上的 faithful success：完成任务、满足全部构造期金标约束，并达到金标最小改动数。差值定义为“单体 − 编译器+符号规划器”。区间按 E/I 配对任务组 bootstrap 10,000 次，条件于当前 seed42 权重；四项点态区间没有多重比较校正。

| 切分 | 单体 faithful | 单体 safe | 单体合法计划 | 管线 faithful | 差值 pp [95% CI] |
|---|---:|---:|---:|---:|---:|
| dev | 90.67% | 94.67% | 100.00% | 98.50% | −7.83 [−11.17, −4.67] |
| tpl_ho | 87.29% | 92.86% | 100.00% | 96.71% | −9.43 [−12.86, −6.00] |
| tool_ho | 38.14% | 39.14% | 81.90% | 91.71% | −53.57 [−59.00, −48.14] |
| struct_ho | 14.29% | 15.71% | 55.14% | 95.86% | −81.57 [−84.86, −78.14] |
| 合并 E/I | 56.37%（1522/2700） | — | — | 95.59%（2581/2700） | −39.22 [−41.85, −36.52] |

此结果支持一个窄而有力的结论：在当前合成任务、固定 1.7B seed42 与当前训练配方下，编译器加确定性规划器在四个切分的 faithful execution 均优于直接生成计划的单体；差距集中在工具名和任务结构留出。结果不证明普遍的架构因果优势，也不能外推到真实任务或训练种子总体。

## N 版行为：正确拆分失败类型

旧审计把 N 版所有非-faithful 行都叫 `none_false_alarm_rate`。这个名字不准确：faithful 失败既可能是模型输出了有效但非默认计划，也可能是模型没有产出可执行计划；单体并不输出约束，因此这里不能称作“编译器误报”。重放后按无效计划、有效默认计划、有效偏离默认计划拆开：

| 切分 | N 样本 | 无效计划 | 有效默认计划 | 有效偏离默认计划 |
|---|---:|---:|---:|---:|
| dev | 300 | 0（0%） | 300（100%） | 0（0%） |
| tpl_ho | 350 | 0（0%） | 267（76.29%） | 83（23.71%） |
| tool_ho | 350 | 0（0%） | 350（100%） | 0（0%） |
| struct_ho | 350 | 8（2.29%） | 342（97.71%） | 0（0%） |

因此模板留出上的 23.71% 是有效计划偏离默认值，不是无效格式，也不是约束抽取误报；结构留出 2.29% 才是无效计划。审计 JSON v2 使用 `invalid_plan_rate` 与 `valid_deviation_rate`，不再使用误导性误报字段。

单体受约束失败的细分也显示结构留出主要失败在计划合法性：tool_ho 为 190 条无效计划、236 条完成但违反金标约束、7 条安全但超过金标最小改动；struct_ho 为 463、127、10 条。dev 和 tpl_ho 没有无效计划。

## 训练量与长度限制

两臂均为 9,000 updates 和 12,000 训练行，但不属于匹配计算量。独立 tokenizer 重放显示三轮总 token：编译器输入 26,061,492、监督 target 2,670,729、合计 28,732,221；单体输入 35,346,477、监督 target 1,056,099、合计 36,402,576。单体 target 为计划 JSON，编译器 target 为约束 JSON。token 数不是 FLOPs；不能据此声称哪一臂训练更省算力。

单体 `elapsed_s=8028.5` 包含初始化、训练、评测和分析，不是纯训练时长。评测生成共 134,105 token；四个切分计时合计 587.4 秒，但没有同一协议的管线端到端计时，故不做速度、成本或延迟优劣结论。

预检显示训练集 12,000 条没有因 1,280-token 训练上限被丢弃。结构留出有 59 条样本的“提示+金标计划”长度超过该训练上限；该上限不用于裁剪评测输入，模型评测上下文为 131,072 token。测试行不参与训练，评测完整输入。

## 结论边界与后续

- 这是探索性修正、单 seed 结果。不能声称架构总体显著优越或等价；训练 seed 变异必须由多 seed 设计回答。
- 两臂训练 target、可学习任务和 token 分布不同；9,000 更新不等于计算匹配。若论文把 E2 作为因果架构证据，仍需等预算或多 seed 的进一步设计。
- E2 不支持延迟、token 成本或美元成本优势；现有信息只支持记录实际训练与评测用量。
- v6 seed44 继续由既有服务器队列独占接力。本轮审计在本机 CPU 完成，没有触碰远端训练进程或占用 GPU。
