## 部署开销

同一 30 条合成请求，1.7B、4B、本次 DeepSeek 零示例与十示例各推理一次。完整编译正确 17、20、17、29 条。中位端到端延迟依次为 2.93、3.45、1.65、2.65 秒。自托管 1.7B 的峰值已分配显存为 3.36 GiB，4B 为 7.72 GiB。两者均在禁止进程创建 IP 套接字的条件下完成加载和推理。同卡固定 512 个输入及 64 个输出 token 后，相比 4B，1.7B 的端到端生成调用中位耗时低 23.2%；进一步隔离 prefill 后，63 个解码间隔的中位延迟低 23.3%，配对的 10/10 任务组更快。[部署与 token 对照](compiler_efficiency_v1.md)

## A003 审批歧义复测

原句仅说缺少签核附件。作者试读提出可能需要补办审批。对冻结测试集中使用此句式的全部 44 条输入（30 个任务组），固定其余文字，另造一版明确豁免和一版明确要求指定批准。两模型各推理 88 次，给两臂同一份公开目录规则。原测试集和原金标保留。下面报告实际恢复角色对的正确数。

| 比较 | 1.7B | DeepSeek 十示例 |
|---|---:|---:|
| 明确豁免时正确省略授权 | 43/44 | 44/44 |
| 明确须批时正确抽出授权双方 | 44/44 | 44/44 |
| 两侧的目标授权均对 | 43/44 | 44/44 |
| 两侧完整记录均对 | 33/44 | 39/44 |
| 明确豁免后，计划安全完成 | 39/40 | 40/40 |
| 明确须批后，计划安全完成 | 40/40 | 40/40 |

执行项限于能找到两份严格计划的 40 条，这两份计划都调用目标工具，一份先获批准、一份没有批准。明确豁免时模型通常能识别，原句是否应解作豁免仍由独立读者判断。原措辞留出共 1,050 条，排除这 44 条后的 1,006 条上，沿用原版完整编译口径，1.7B 820/1,006、DeepSeek 845/1,006。原口径对应 849/1,050、889/1,050。此为敏感性分析。[审批复测](../outputs/approval_wording_v1/scores.json) · [原成绩敏感性](../outputs/authored_wording_v1/ambiguity_sensitivity.json)

## 规划器实验、原 GRPO 与修订的贡献②

| 实验 | 数据 | 说明 |
|---|---|---|
| 格式预热 | 严格任务完成 0→80/80，安全完成 0→19/80 | 预热主要解决规划输出不可执行的问题，合规仍有改进空间 |
| 功能门控与加法奖励 | 在 32 个多约束采样组中，组内归一化后可辨别差异 0/32 | 在这些主要能完成任务的轨迹上，门控没有提供独立训练信号 |
| 原责任动作奖励 vs 整轨迹奖励 | 3 个种子各 120 道开发题，净增 +1、0、−1 道 | 无稳定收益 |
| 预防动作奖励 vs 整轨迹奖励 | 3 个种子各 90 道开发题，净增 0、+2、−2 道 | 修改后仍无稳定收益 |
| 给修复动作加训练权重 | 3 种样本顺序各 80 题，净增 +1、−3、−6 道 | 没有复现稳定改进 |
| 冻结训练权重留出复测 | 共 2,160 条预测，整轨迹奖励对仅功能奖励在未见措辞各增 0、1、3 道，在未见工具名增 1、−1、1 道，每种子每子集 80 道 | 原 GRPO 不宜作为论文的成功算法主张 |
| 同四候选，预测约束重排 → 可验证单动作修复 | 安全完成 682→1,144/1,400，增 464、损 2 | 能够修改候选计划会扩大可达安全解的范围 |
| 同编译输出的符号规划 | 规范化收尾后 1,149/1,400 | 与上述 1,144 接近；规划方法搜索预算不同 |
| 改变工作流深度 | 一组 80 题安全完成 70→9，按新公开流程补齐缺失阶段后 70/80。另一组受约束题 54→57/64，符号对照 64/64 | 支持公开流程结构影响搜索结果，适用范围仍是合成环境 |

| 同 1,400 道受约束题，编译器和候选来源交叉更换 | 0.6B 编译器 | DeepSeek 编译器 |
|---|---:|---:|
| 第一份候选规划器 | 1,144 | 1,255 |
| 另一份同底座、同数据、不同训练样本顺序的权重 | 1,199 | 1,292 |

初始 256 道失败中有 118 道在已定义的搜索范围内有安全方案。保持候选不变，改编译器救回其中 112 道，另损失原本成功的 1 道。余下 138 道在原范围内无解，改候选来源后其中 47 道转为安全完成。原训练结果支撑有限；这个 2×2 对照能区分读错约束和候选搜索受限。[规划结果与贡献取舍](contributions_submission_decision.md) · [含各种子、各开发子面板和失败项的台账](experiment_log.md)
