# 约束解析、传播与具身扩散规划：近邻核验及研究决策

日期：2026-11-25。范围：用户最新架构设想、Qwen建议、具身/VLA的扩散思路。所列【事实】来自本地实验或本轮核对的原文；【推断】是对其适用范围的判断；【假设】尚未取得本项目实验支持。不是完整系统综述，不保证无重合，也不估计录用概率。

最新目标约束：用户明确“单目标是CCF-B”。岗位截图仅为思路来源，不构成求职导向、多模态转型或机器人任务的目标。所有候选按新颖性、证据强度与资源成本筛选；不因为岗位相关、模型名称新或模块多而扩大研究范围。

## 1. 结论

可以用“自然语言约束→规划期间使用约束→验证执行”组织一篇论文，但这条流程本身已存在。借鉴具身规划的多解生成、局部修复和闭环执行有研究价值，不能把“用了扩散/GNN/CLIP”当作已成立的创新。

【事实】ATLAS已有前置约束管理器和有/无消融；Dr.Aid早在2021年就处理数据流中的治理规则传播、编辑、删除；CaMeL把信息流追踪用于LLM agent。扩散方面，DiG-Plan、CoDA和Plan-and-Patch分别覆盖工具图多候选、去噪中的策略约束、局部计划修复。

【决策】保留现有编译器及E/I/N资产。将“在约束干预下生成或修复多种可行DAG”列为小规模候选研究，先证明任务需要和已有方法的具体不足，不立即改主表或启动4B扩散/GRPO组合。GNN和扩散可以同时出现在实现中，没有必须二选一的理论理由。

## 2. Qwen观点：哪些能保留，哪些必须改

| 说法 | 核验与裁决 |
|---|---|
| 用约束生命周期串联三部分 | 【推断】有助于组织问题和接口；不是新颖性证明。论文可是一项主方法加一个基准，不必硬凑三个独立算法。 |
| 加解析器能提高约束满足，是新贡献 | 【事实】[ATLAS](https://arxiv.org/abs/2509.25586v1) §3.1–3.2、Fig.3、Table5a已有Constraint Manager→Planner/Checker，并做了移除管理器消融。其特定TravelPlanner开发设置硬约束宏观通过率60.00→74.44%。本项目仍需该对照，但不能首次主张这一通用架构。 |
| 数据流上的约束传播无人做 | 【错误】[Dr.Aid](https://arxiv.org/abs/2110.01056v1) §3.2.1–3.2.2区分data rule/flow rule，包含propagate、edit、delete及MIMO数据流；[CaMeL](https://arxiv.org/abs/2503.18813v2) §5.3–5.4追踪每个值的来源、允许接收者和依赖，执行工具前检查策略。前者是治理规则，后者是agent安全，不等于本项目全部五类约束，但足以否定“传播空白”。 |
| GNN只能建依赖，不能传播约束 | 【错误】消息传递网络可以学习传播、可行性或代价；能表达不等于能可靠保证。确定性传播也可作为强基线，选择由任务与实验决定。 |
| 必须放弃GNN，不然会被拒 | 【无依据】近邻拥挤意味着需要具体差异，不意味着禁用一种架构。[CONSTRAINER](https://arxiv.org/abs/2611.10627v1)、[GNNVerifier](https://arxiv.org/abs/2603.14730v2)、[GRAFT](https://arxiv.org/abs/2605.11706v1)是需要比较的近邻。 |
| 匹配显著优于生成、便宜一个数量级 | 【未证实】我们的冻结双塔小试对比损失与排序损失两seed准确率完全同数，未过门槛；它也不是公平的匹配/生成端到端比较。五种类型封闭不等于数值、scope及组合空间封闭。 |
| LLM解决冲突 | 【需限定】LLM可建议替代工具、重排或补步骤；不得自行取消硬约束、授权自己或改金标。没有可行解时报告冲突或请求授权。最终验证仍依据原要求。 |
| A不出域且B导出文件，所以冲突 | 【不必然】导出到域内文件并不等于出域，需知道接收者、环境、数据来源和转换语义。 |
| 七类国家官方约束、首个可信数据空间数据集 | 【未核实】没有取得对应标准条款和穷尽数据检索证据。保留五类冻结schema；不因二手建议改标签或写“首个”。 |

【事实】[IMR-LLM](https://arxiv.org/abs/2603.02669v1)摘要描述析取图与确定性求解器；本轮未核验其发表会场或完整方法，不能拿它证明某种模块组合的普适有效性。GFlow/VECO-GNN/Grapheon RL/ACT/CLM所指具体原文未完整定位，暂不承担结论。“IEEE”“Springer”是出版方，“UIUC”是机构，不是充分的发表层级证据。

不同约束不能统一做“沿边复制”：隐私/用途限制需要数据来源及可信转换规则；授权受操作与scope控制；预算是总额/剩余资源；并行时限通常依赖关键路径与调度。传播规则可确定性计算，不代表真实隐私自动受保证。转换后解除限制必须有声明且可信的契约。

## 3. 具身/VLA有哪些思路确实可借鉴

【事实】[Diffusion Policy](https://arxiv.org/abs/2303.04137v5)用条件扩散表示动作分布并结合滚动时域控制；[Diffuser](https://arxiv.org/abs/2205.09991v2)把轨迹去噪、目标条件和inpainting用于规划。它们支持“学习多种可行行为”这一路线。Diffusion Policy本身是视觉运动策略，不应笼统称为语言条件VLA；借鉴的是动作生成与闭环思想，不是搬视觉输入或机械臂控制器。

| 具身思想 | 工作流中的对应 | 迁移时的限制 |
|---|---|---|
| 多峰动作分布 | 同一请求和约束下存在多个工具组合/依赖结构 | 自回归采样也能多解；不能用“AR只能输出均值”作动机。 |
| 动作块联合建模 | 同时考虑多个节点/边/参数的兼容 | 图离散、可变长且有拓扑不变性，不能直接给工具编号加高斯噪声。 |
| 目标/约束引导去噪 | 根据预算、时限、数据流和前置依赖筛选或调整候选 | 软梯度引导不保证硬约束；离散checker未必可微。 |
| 轨迹补全/局部重规划 | 保留仍有效子图，仅更新受影响区域 | 局部区域可能无法修复，需允许扩张；完成的有副作用动作不能假装回滚。 |
| 闭环执行 | 工具返回后更新状态，再规划后续 | 这是新增动态任务；当前单轮确定性数据不能证明动态适应性。 |

正确目标可写为条件分布 p(G | request, C, tools, state)，从中取得若干完整工作流G。不是对若干图逐边求平均。“均值撞障碍”针对单一连续回归输出的经典问题；自回归分类/序列模型与之不同。扩散的候选优势是可反复修正整组决策、并行填补结构，其成本和有效性都需测量。

例：在相同处理目标下，本地工具组合甲较慢较便宜，组合乙较快但更贵，两者均满足隐私、预算与截止期；改变截止期后可能只剩乙。模型需分辨哪种完整组合仍可行，而不是混合两条路径中的不兼容节点。这是示意例，不是现有数据的观测结果。

## 4. 扩散方向的直接近邻

以下已获取原文，并核对指定方法段；没有把其他论文的数字当作我们的预期收益。

| 原文与核对位置 | 已经覆盖的机制 | 对本项目的影响 |
|---|---|---|
| [LayerDAG](https://arxiv.org/abs/2411.02322v2)，§3 | 按拓扑层自回归生成，每层节点/边用离散扩散；BiMPNN编码＋Transformer，支持条件生成 | “GNN/Transformer＋扩散＋DAG”已有直接先例；DAG合法也不代表满足用户约束。 |
| [DiG-Plan](https://arxiv.org/abs/2606.05728v1)，§3–4 | 扩散提出多个工具集合，AR预测依赖边，部署可用价值函数选择；与AR多采样比较 | “扩散提出多种工作流”已被直接研究。其工具/边参考相似度与我们的约束行为目标不同，但换指标本身不是新算法。 |
| [CoDA](https://arxiv.org/abs/2610.15177v1)，§4–5 | 将上游给定策略用于扩散去噪中的投影；工具、参数、URL、来源、信息流等约束；完整多token值一致性 | “前置约束＋扩散期间约束投影”也有近邻。不能说它只做格式/单token，也不能未经实验说本项目更安全。 |
| [Plan-and-Patch](https://arxiv.org/abs/2610.10786v1)，§4 | 生成结构化计划，失败后定位区域，保持上下文并补全；对照AR的FIM局部修复 | “扩散局部修复”不是空白。其交互评估从初始环境重放，不能直接等同保留真实已执行前缀。 |
| [LTLDoG](https://arxiv.org/abs/2405.04235v2)，§III | 测试时LTLf时序约束，用满足度值函数引导轨迹去噪 | “扩散考虑先后关系”已有先例；离散DAG的不可微联合约束仍需专门实现。 |
| [The Bitter Lesson of Diffusion Language Models for Agentic Workflows](https://arxiv.org/abs/2601.12979v3)，摘要与章节结构 | 报告特定dLLM在具身反馈、严格工具格式方面的失败，提出混合分工 | 本轮仅用于风险提示，不将其结论推广到所有扩散模型，也不据摘要声称复核全部实验。 |

与Qwen传播建议合起来看，两个方向都不能按“别人没做过”直接立项。与最近论文不同的任务边界，是提出新机制的起点，不是新颖性已经成立的终点。

## 5. 可继续研究的具体候选

【假设】围绕“约束变化引起的跨节点联动编辑”研究一个小型、条件化的离散图生成/修复器，显式利用检查器返回的冲突位置和资源剩余量，学习选择修复区域及扩张时机。比较其是否能在固定生成与验证预算下保留多个可行方案，并减少无关修改。约束编译器提供条件，图模块负责联合规划，E/I/N与干预配对数据提供验证。

这一描述仍与Plan-and-Patch、CoDA和经典约束规划接近。真正需要证明的区别应落实为一种明确的区域选择/联合更新/预算分配规则，而不能只是换成“跨节点”措辞。若简单规则选择区域已足够，不必再训练一个神经选择器。

一个可实现的候选结构是：现有小模型提取类型化约束；小型图/Transformer去噪头预测工具实例、依赖边和参数；已声明的硬检查器输出可用反馈；从最终合格候选中按公开任务代价选择。可用层级表示保证无环，使用离散mask而非对工具ID做连续插值。训练时的多个正确计划可以来自求解器；推理输入、选择器和修复反馈不得访问金标约束或金标最优解。

不把Qwen自回归权重改个损失就称为扩散模型。首轮只考虑小型结构头，语言编译器固定；不预先启动8B dLLM，不同时堆GRPO/CLIP。扩散能否成立和GRPO能否改进是两个研究问题。

理论边界：确定性无环编码最多保证图无环。逐字段允许值不保证预算/时序联合可行，局部mask可能误删可行解；最终校验保证也只相对于所给形式约束和工具契约，不能修复上游漏提约束。任何硬保证都应写明条件、拒绝行为和未覆盖的真实环境风险。

## 6. 先做什么，以及何时停止

以下为下一阶段协议草案，没有新增训练结果；当前冻结v5/v6实验继续按原队列。

### S0：必要性与数据审计

1. 在train/开发任务上将最优计划按工具实例、参数、真实数据流及执行语义去重。区分不同工具组合、不同依赖结构、纯拓扑排序/编码差异。先证明存在值得建模的多解，不用字符串不同来充数。
2. 审计约束小改动是否真的改变可行集合，以及局部修复是否需要跨节点协同。可满足、不可满足和无需修改分开；一切信息必须来自公开请求、工具目录和政策。
3. 同预算计时确定性求解器、随机可行采样/启发式、AR多采样及AR局部修复。当前世界求解器已在922开发子集全对，中位0.632ms（不含语言解析）；因此仅在该世界用扩散替代求解器没有效率动机。
4. 若扩展任务，只增加明确有用途的依赖深度、资源耦合或动态反馈，写成新版本，保留旧结果。不得为了打败强模型隐藏信息、改测试标签或制造无解但要求成功的题。

### S1：最小机制试点

先用oracle约束隔离后端，但结果明确标为诊断；模型选定后再接实际编译器做端到端。固定数据量、语言特征、有效参数规模及开发预算，比较：

| 臂 | 作用 |
|---|---|
| 确定性求解器/搜索 | 必要强基线，计入全部求解与校验开销 |
| AR多采样＋同一检查/选择器 | 排除候选更多带来的优势 |
| AR局部修复＋相同上下文/反馈 | 排除只因额外反馈或FIM能力 |
| 普通离散扩散＋最终检查 | 判断扩散本身是否有帮助 |
| 扩散＋候选新干预机制 | 只改变拟研究的跨节点更新规则 |

小结构头先seed42/43；开发增益方向一致后才增seed44和新封存确认集。等候选数只是一个控制，还需相同墙钟/验证调用上限的比较；记录总模型前向次数、生成长度、GPU时间、峰值显存、API费用。计入离线求解标签成本，不假称训练免费。

主指标是实际被选择并执行的工作流成功且满足约束；多解场景保留最小改动/质量要求，并分别报告，不把不必要编辑当多样性。辅助指标包括语义去重后的可行解覆盖、约束变化后的修复成功率/无关修改数、N误报和不必要修改、超时与拒绝率。oracle-best-of-k只作候选上限诊断，不能冒充部署成功率；精确解空间覆盖率仅在可枚举世界报告。

按同源任务组做配对bootstrap，E/I/N不当三个独立样本；训练seed波动另报。初筛可采用事先锁定的实用门槛，例如两个seed主要行为指标均提升至少3pp，或同等质量下总成本明显下降；选择哪条及具体容差必须在run前定，不在看结果后换主指标。两seed只能初筛，不能声称稳定总体结论。

停止条件：多解主要是编码重复；简单求解器已满足实际延迟；收益仅来自更多调用；N和硬约束显著退化；效果随seed反转；候选机制不能区别于已有约束投影/普通局部修复。失败时保留报告，停止扩规模，不为“让GPU忙”重复无依据实验。

### S2：解析器与规划器联合证据

使用相同规划器检查点、相同完整请求与工具目录做解析器开/关×新规划机制开/关的2×2；增加等调用预算的普通摘要/分解控制。解析器方法在开发集上选择后冻结，强PE也可作为解析器实现，不需要强行让小模型胜过它。oracle解析器仅用于归因。若解析器不带来增益，就不能把其存在单独宣传为方法贡献。

## 7. 数据与论文定位

E/I/N继续保留：显式、可恢复的隐式、无有效附加约束/豁免。不是明确/不确定/不可恢复。新增多解与约束干预标注应补充可行计划集合、语义等价关系、冲突证据及修复影响区域；不将任意另一条正确计划作为难负例。执行witness验证形式可行，不等于自然语言获得独立人工验证。

【推断】有机会形成“约束接口驱动的工作流生成方法＋可执行干预基准”，但当前还没有稳定的新方法收益，不能说三项创新已经足够CCF-B。能否支撑投稿取决于具体机制相对直接近邻的区别、可复现增益、代价、公平基线及任务有效性；增加扩散这个模块名称不会自动提高论文档次。

本轮六次CLIP式冻结头试点已完成：对比与排序准确率均为66.67%/71.35%（seed42/43），未通过扩张门槛。此前GNN试点也没有独立增益。这些结果不否定所有对比/图/扩散方法，但要求下一步先证明需求和机制，再动用更大的模型。

## 9. 多模态候选与CCF-B单目标裁决

用户补充多模态Agent岗位截图后提出“多模态工作流可信约束”，随即明确唯一目标是CCF-B。截图不是论文证据，岗位匹配不进入研究选题目标。

【事实，以下仅摘要核验】新增检索发现：

- [TRACER](https://arxiv.org/abs/2605.09934v1)：多模态工具观察到答案句子的结构化来源记录、验证与局部强化学习信用，限制“多模态证据绑定本身首次”的主张。
- [MMA-SafetyBench](https://arxiv.org/abs/2610.19384v1)：跨GUI、文档、视频等任务的视觉语义劫持与授权任务偏离评测。
- [Penny Wise, Pixel Foolish](https://arxiv.org/abs/2604.16515v1)：截图驱动多模态agent中的价格约束绕过与防御。
- [DWIM](https://arxiv.org/abs/2503.19263v3)：工具感知视觉推理中的工作流数据生成与微调。
- [PriMobiBench](https://arxiv.org/abs/2609.13873v1)：截图驱动agent的视觉隐私泄漏、画像风险及遮蔽缓解。

【推断】“多模态＋可信约束＋工作流”不是未经研究的组合。若只是将文本渲染成图片再OCR，增加的是识别难度，未必产生新的规划问题。要立项，须证明跨模态信息改变约束或规划决策，并与OCR→文本编译、普通VLM规划及已有安全/来源追踪机制区别开。屏幕或文档中的不可信指令不能自动提升为用户授权。

【当前裁决】不将多模态设为主线，不同时开启多模态、扩散和GRPO训练。优先复用现有资产，检验约束干预下的跨节点联合生成/修复是否存在具体、可重复且与近邻不同的机制收益；扩散只是一个实现候选。若该机制在文本可执行世界中已不能超过简单基线，增加视觉输入不能被用来掩盖失败。只有明确的模态间证据绑定缺口值得单独研究时，才将多模态列为新立项而非装饰模块。

CCF-B没有“堆齐三个创新点”或“击败某个强模型”这一单一充分条件。当前没有足够证据说新方法已稳住，也没有依据保证任何候选方向录用。应尽快用预先设定的开发门槛淘汰无收益分支，保留失败结果；主论文集中于一个能经受直接近邻比较的方法贡献及其数据和实验支撑。
