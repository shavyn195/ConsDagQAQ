# 本地约束编译与 DAG 规划：定位、原文核验和证据要求

日期：2026-11-26。目标：CCF-B。本文回应“可信数据空间＋本地小模型＋约束解析/规划分离”的新定位，继承已有实验，不将改写动机视作新增实验结果。

## 结论

【判断】这一定位成立，也不要求本地小模型击败 DeepSeek。可以继承 ATLAS 的约束管理思路及 Beyond ReAct 的 DAG 规划思路；论文贡献可以由具体方法、基准及系统性实证组成，不必凑三个独立的新算法。

【边界】本地部署是场景条件，普通 SFT 是实现选择，已有的解析/规划分离是继承架构。三者相加不会自动成为新的方法贡献。只胜过未经调优的自家基线也不足以支持优越性；须在明确资源限制下，与有竞争力的本地方案比较约束满足、任务完成及总成本。

【当前判断】有继续冲击 CCF-B 的合理研究路径，但尚不能称创新已经稳住。需要建立具体方法机制的新增价值；换成“可信”叙事不能补上这项证据。此处不估计录用概率。

## 1. 可信约束应如何定义

建议用“数据治理与使用控制约束”作为操作性定义，可信数据空间作为应用背景。这里的“可信”指所需满足的政策条件，不意味着模型或系统已经具备可证明安全性。

| 来源与原文范围 | 支持的约束概念 | 与现有五类的关系及边界 |
|---|---|---|
| [W3C ODRL Information Model 2.2](https://www.w3.org/TR/odrl-model/)，§2.5、§2.6 | 对资产的许可、禁止、义务；许可生效的前置义务；有参数的逻辑条件 | 为结构化表示和审批前置提供概念依据。它是标准，不是本项目五类约束的官方分类，也不自动赋予本项目 ODRL 合规性。 |
| [Access control for Data Spaces](https://arxiv.org/abs/2504.13767)，摘要、引言、§II | 对数据对象、属性和操作的细粒度授权；持续评估、撤销；数据所有者管理政策 | 支持授权和数据处理范围的应用动机。当前 `tool_auth` 只是所选有限工具世界中的代理语义，不是完整访问控制实现。 |
| [Dr.Aid](https://arxiv.org/abs/2110.01056v1)，§3.2.1–3.2.2及既有全文笔记 | 数据治理义务、触发条件、随数据流传播及规则修改 | 支持审批/审计类义务和派生数据政策的讨论。当前普通 `order` 不等于完整义务传播；一般依赖也不必然是安全约束。 |
| [Styx](https://arxiv.org/abs/2604.04082)，摘要及引言 | TEE 与 sticky policy，使用中数据、派生输出和整个生命周期的政策执行 | 表明信任边界及执行机制比单纯“在本地”更重要。本项目没有实现其 TEE 保护，不能引用为已有安全保证。 |

现有 `privacy`、`tool_auth` 及与审批有关的 `order` 可讨论为治理相关子集；`budget`、一般任务 `deadline` 通常属于资源/QoS约束。用途限制、保存/删除期限、审计义务和派生数据政策属于可扩展类型，不能写成已经实现。任务完成时限与数据保留期限也不能混同。

保留冻结的五类数据和结果，按预先明确的治理/资源切片补充分析，不删除难例或事后重新标注以改善主表。E/I/N继续表示显式、可恢复隐式、无有效额外约束；N不是歧义或信息不足。此定位不启动历史 C1–C5 实验，也不恢复正式人审。

## 2. 本地部署动机的正确范围

【建议设定】研究禁止将敏感请求、工具元数据及治理政策发送给外部模型服务，且推理显存/延迟受限的组织内部部署。具体资源上限应来自目标设备并实测，不能根据哪个模型输赢倒推上限。

这是一类合理应用，不是所有可信数据空间的共同强制要求。数据空间仍需受控共享；本地模型只限制敏感推理信息的处理边界，不意味着所有工具或所有数据交换都禁止跨组织。私有云、机密计算以及本地部署的更大开源模型都是可能替代方案。“强模型都不能本地部署”应改为“所比较的外部托管模型服务不满足本实验部署条件”。

需要检查整个推理链：本地解析器之后，若云端规划器继续收到原请求，不能称端到端本地。结构化约束也可能暴露患者类别、业务用途等敏感内容。推理日志、工具目录和验证反馈同样要纳入边界。训练使用敏感数据时，训练/标注服务另需符合相应条件。

本地化既不自动产生速度优势，也不自动消除泄露、提示注入或越权风险。本论文优先主张给定形式语义下的规划约束满足；如声称抵抗某种攻击，需要另给威胁模型与实验。

## 3. 能否接着 ATLAS 做

【事实】ATLAS 原文 Table 5(a) 在 TravelPlanner validation、Gemini-2.5-pro、5次检查及10次交错检索条件下，对比有/无 Constraint Manager：Hard Constraint Macro 为60.00%/74.44%，Final Pass为30.00%/44.44%。

【结论】可以明确引用并继承。这是特定实验中的作用证据，不是“任何规划器加解析器都会更好”的定理。ATLAS 的多代理约束管理也不与当前一次性前置解析完全相同，适配时需说明简化范围。

论文的新问题可以是：在本地资源受限条件下，如何将用户约束转成可检查对象，并让规划与修复在较低成本下保留这些要求。需要自己的无解析器、同调用预算分解、现有约束管理适配等对照。将 ATLAS 换成4B并做普通SFT本身只是迁移实现，不能独立宣称新的架构原理。

## 4. Beyond ReAct 的贡献结构能否借鉴

【事实】用户给出的三条与原文第2页一致：planner-centric plan–execute及DAG规划器；ComplexTool-Plan难度分级基准；系统实验效果。原文确实没有要求每条贡献都是一个新算法。

需要区分两种分离：Beyond ReAct 是规划与执行分离，ATLAS 包含约束管理与规划的职责分离。两篇可共同提供设计依据，但不能相互替代。

Beyond ReAct还在外部基准StableToolBench上评估，并使用GPT-4o执行器。因此它不证明完全本地系统的效果。其RQ3报告Qwen3-8B(RL)平均SoPR为59.8%，GPT-4(ReAct)为48.2%；正文同时承认DTA-Llama的SoPR更高，强调自身非迭代全局规划及较少决策轮次。不能把摘要的“SOTA”推广成所有范式、所有成本维度全面最优。推理轮数也不能直接替代墙钟延迟。

【建议】可以借鉴“方法/系统＋基准＋系统性证据”的贡献结构。我们当前更适合检验“指定本地资源预算下的效果—成本优势”，待数据支持后再决定是否使用有范围限定的SOTA措辞。只在自建数据上打败弱基线，不足以建立广义SOTA。正式发表状态未在本轮独立核查，按实际读取的arXiv版本引用。

## 5. 将①②③组织成一篇论文

共同问题：**资源受限的本地Agent，如何把自然语言中的治理要求可靠地落实到DAG计划及其修改中？**

| 工作包 | 定位 | 需要证明什么 |
|---|---|---|
| ① 本地类型化约束编译 | 延续小模型及五类接口；SFT为现有起点，PE/匹配为替代实现 | 在有竞争力的本地基线下，显式接口的净收益；解析错误如何影响下游；收益不能只来自多一次调用或额外监督 |
| ② 全局约束一致的有界DAG修复 | 方法候选：区域外约束摘要、局部修复及必要时扩大区域 | 相比全局重规划、普通局部修复及确定性求解，在同信息/反馈预算下减少违规或代价；尚未证明新颖性与有效性 |
| ③ E/I/N配对可执行基准 | 保留现有基础；若做动态修复，另立版本补充变更任务 | 语言可恢复性、字段与行为两条评价轴、结构/工具泛化、无需修改和不可行样例；生成器正确性不等于现实代表性 |

①与②合起来可作为一条完整方法贡献，③作为数据贡献，再以实验发现作为第三条论文contribution；不必把每个工作包都硬写成独立算法创新。

②不能按“BFS定位＋冻结其余节点＋小模型修改＋验证”直接宣称新颖：已有[Atomic Task Graph](https://arxiv.org/abs/2607.01942v1)覆盖通用局部修复机制，见前次审核。区域外全局预算/时间/政策摘要与扩域策略是待检验的细化问题，仍需与增量求解、程序切片等比较。当前任务以静态规划为主，动态变更实验必须有明确的新协议，不能混入冻结主表。

## 6. 什么才是公平、有说服力的比较

| 对照 | 回答的问题 |
|---|---|
| 同一本地模型直接根据完整请求生成DAG；包含合理PE和经过训练的直接规划器 | 收益是否只是训练、任务格式或提示差异 |
| 同本地模型、相当总调用预算的通用分解规划 | 收益是否只是多一次思考/模型调用 |
| 本地ATLAS式约束管理适配；Beyond ReAct式训练DAG规划器适配 | 是否超过有竞争力的既有机制；适配版明确标注，不能当官方复现成绩 |
| 编译器＋固定规划器；编译器＋同规划器＋候选修复机制 | 分别隔离①和②的净作用 |
| 确定性求解/最小改动搜索 | 在当前可求解的小工具世界中，是否真的需要神经规划/修复 |
| DeepSeek PE及资源允许时的更大本地量化模型 | 外部能力参考及真实部署替代方案；不能只用参数量排除可在同硬件运行的模型 |

优先做决定方向的最小对照，不一次性启动全部大训练。云模型保留为外部能力参照，不称数学上界；本地ATLAS/Beyond适配可先选最直接的近邻开展。原始请求、工具目录、可用政策、反馈信息和候选构造需公平。规划器不因无解析器而被隐去原请求中的约束。

训练臂报告数据量、监督内容和计算成本；推理统计编译器、规划器、验证/修复及回退的总token、墙钟、峰值显存与调用数。参数较小不保证总延迟更低；两个4B模块也不能按“只用了一个4B”计账。若同卡串行加载，要计入真实调度成本。

主指标同时涵盖任务完成、全部有效约束满足及多余修改；保留strict/core/record指标，不能只看可能掩盖字段错误的faithful。单列N误报/误改、拒绝与错误拒绝、修复回退。多seed保留失败seed；同源E/I/N和变更题按原任务分组进行配对统计，不视为独立样本。成本报告不能只统计成功题。

冻结v5/v6的H2仍按原协议报告失败或未达标；新的本地比较属于后续研究问题，不能回头说原非劣效检验已经成功。

## 7. CLIP、GRPO与SFT的安排

【判断】CLIP式匹配完全可以作为对照，不必承担主创新。候选必须能根据公开工具契约和请求在部署时构造；不能从金标生成候选再与自由生成作端到端比较。多约束、参数值和N版空选择都须可表达。

【事实】已有六次冻结表示投影头试点中，对比损失没有超过排序损失；其候选来自oracle。它不能证明CLIP已优于SFT，也不能作为完整可部署系统结果。

先用已训练SFT接口验证①与②的架构问题；若具体错误分析表明匹配或RL能改善某一瓶颈，再投入。CLIP/GRPO不是为使贡献列表更丰富而必须加入的部件。选择方法只用开发集，正式测试报告规则固定。
