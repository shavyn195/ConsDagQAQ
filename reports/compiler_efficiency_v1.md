# 请求级约束编译的部署和推理开销

在受控工作站部署编译器，可以在本地处理请求原文和工具目录。这项实验把部署条件、单请求延迟、提示长度和输出正确性放在同一张表中。面板来自已有的 60 条合成改写，从两个留出切分的五种约束类型各抽一个任务组，共 10 组。每组包含有效要求、无关历史信息以及二者混合三种输入。四个系统各测 30 次。没有新增人工撰写的测试样本。

| 系统 | 平均输入 token | 平均输出 token | 端到端中位数 | P95 | 完整正确 | PyTorch 峰值已分配显存 |
|---|---:|---:|---:|---:|---:|---:|
| 1.7B 本地 | 724.7 | 100.8 | 2.93 秒 | 14.43 秒 | 17/30 | 3.36 GiB |
| 4B 本地 | 724.7 | 65.0 | 3.45 秒 | 5.75 秒 | 20/30 | 7.72 GiB |
| DeepSeek 零示例 | 744.7 | 47.1 | 1.65 秒 | 2.71 秒 | 17/30 | 服务商托管 |
| DeepSeek 十示例 | 8,731.7 | 65.2 | 2.65 秒 | 3.74 秒 | 29/30 | 服务商托管 |

租用的 RTX 4080 SUPER，bf16，既有 LoRA 适配器，单条请求，贪心生成。所有模型均预热一次，端到端从准备提示计到获得文本，不含首次加载或下游规划，API 计入网络与服务时间。两个本地模型依次使用同一块卡，API 在该机器上单流调用。每个输入上的 API 零示例与十示例调用顺序均衡。完整正确要求顶层状态、约束集合、精确参数、风险等级、按公共目录推导的作用范围和逐字证据正确。不同服务的分词器不同，原生 token 数用于报告各自用量。零示例的提示文本内容与本地逐条相同。

**模型规模与延迟。** 推理分为处理输入的 prefill 和逐 token 解码。对相近的稠密架构、相同精度与硬件，在 batch 1 下读取权重的开销随模型规模增长。生成时间还取决于输出长度。因此另取上述 10 组的各一条请求，验证两个本地分词器得到的输入 token ID 逐个一致，截取 512 个输入 token，各强制生成 64 个 token。首轮固定长度调用（包含 prefill）中，1.7B 与 4B 的中位耗时为 2.395 秒和 3.117 秒，前者耗时低 23.2%，等量工作下的速度比为 1.30。固定长度测量只计 GPU 生成调用并同步，截取后的文本不参与质量评分。

为把 prefill 与解码分开，又在同一块 RTX 4080 SUPER 32GB 上分别加载 1.7B 和 4B 对应的 bf16 LoRA 适配器，固定 batch=1、512 个输入 token 和 64 个输出 token，对同一 10 个任务组按相反顺序各重复一轮。每次只统计第 1 个和第 64 个 token 的同步墙钟时间差，即 63 个逐 token 解码间隔；模型切换后先用一条独立请求预热。1.7B 的两轮按任务组中位数为 **2.355 秒（37.38 ms/token，26.75 token/s）**，4B 为 **3.071 秒（48.75 ms/token，20.51 token/s）**。因此在这个受控设置下，1.7B 的纯解码延迟低 **23.3%**，速度约为 4B 的 **1.30 倍**；10/10 个任务组的配对中位数均更快，按两轮逐轮比较为 9/10 和 10/10。两轮输出哈希对每个模型均 10/10 一致。任务组配对差值的中位数为 0.725 秒；以任务组为单位做 20,000 次固定种子的 percentile bootstrap，描述性 95% 区间为 0.535--0.846 秒。该结果支持“同硬件、同生成长度下，小模型解码更快”的本实验结论，但样本只有 10 个任务组、只比较两个 Qwen3 尺寸，不能外推到所有硬件、batch 或模型架构。

自然结束时，1.7B 在 30 条里有 21 条快过 4B。三条 1.7B 回答生成到 384 个 token 的上限，这三条也是最慢的三条。逐请求配对时间差的中位数为 0.39 秒，按 10 个任务组重采样的描述性 95% 区间为 −0.16 到 0.81 秒。在此次运行的端到端时间上，两个 API 配置的中位数均低于 1.7B。30 个观测的 P95 对少数长回答很敏感。

**输入与输出。** 在同一个 API 内，十示例平均比零示例多 7,987 个输入 token，这部分直接来自示例及其消息封装。小编译器与十示例强模型相比，平均输入减少 91.7%，完整正确分别为 17/30 和 29/30。按服务商日志，十示例的全部输入中有 97.5% 命中缓存，零示例则为 59.6%。费用应按未缓存输入、缓存输入和输出各自的单价计算。本地成本还取决于用卡小时、实际利用率及训练摊销。本实验只报告实际用量，没有测出单位货币成本优势。

**可信环境的含义。** 两个本地进程在模型加载之前禁止创建 IPv4、IPv6 套接字并检查系统返回拒绝，随后完成各 30 次编译。模型文件和适配器预置，推理无需外部模型服务。此项验证覆盖该进程的模型调用路径。在机构部署时，可信边界还取决于宿主机、日志、访问权限和后续规划器的部署方式。这里用租用服务器模拟自托管推理，输入均为合成任务。
