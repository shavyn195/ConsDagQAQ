# CCF-B 可投性审计：冻结 v5 与尚未运行的 v6

日期：2026-11-24。结论针对“是否具备值得送审的完整论文证据”，不是录用概率，也不是 CCF 官方统一的投稿准入规则。目标会议/期刊尚未指定，最终还需按具体 venue 的范围、稿件类型和投稿规范核对。

**当前尚未达到研究证据层面的投稿就绪。主缺口已不是 v5 的 1.7B/4B 三 seed，而是独立语言有效性、与最近邻工作的实质差异、保留贡献所需的可辨识证据，以及 v6 完整同版本对照。H2 失败可以如实进入论文；“一定打平 DeepSeek”不是投稿的必要条件。** 更可行的主线是受控合成约束编译基准与失效诊断，而非“通用可靠编译器”“新奖励算法”或“小模型全面接近强模型”。

本审计分清三类证据：已保存的 v5 测量；本地 v6 程序验证；尚未发生的 GPU/API/人工实验。文中成本和概率是资源规划判断，不能当实验结果。没有连接服务器、启动训练或调用 PE API；没有 commit/push。

## 2. v5 → v6 补上了什么，尚未补上什么

| 缺口 | v6 当前状态 | 论文可用边界 |
|---|---|---|
| N 的 malformed fail-open | 已修复；三通道报警与 union 分开 | 可以声称评测契约更严格，不能声称已提高模型理解能力 |
| 数据程序一致性 | 独立 replay、gold/witness/必要性、跨切分检查 PASS | 验证的是形式世界中的生成产物，不证明自然语言 gold 可恢复 |
| 独立类型组合留出 | 已实现 privacy+tool_auth；任何包含该对的超集也从其余切分排除 | 只有一个 pair，不能概括全部组合泛化；筛选改变分布，不能叫纯因果干预 |
| BF16 硬约束 | 本轮修复；runner、queue、plan、analyzer 均一致 | v5 原本已是 BF16，这是避免回归，不是新的算法增益 |
| 三 seed 稳定性 | v5 已显著暴露；v6 未测 | 不能用 dev 满分、低 loss 或单 seed 结果宣称 OOD 稳定 |
| 完整字段与行为的联系 | 仍未解决 | type+params 驱动规划；scope/state/severity/evidence 的输出正确性需独立报告 |
| 独立人类可恢复性 | pending | 不可声称 I 对读者无歧义、N 等价真实业务“无需约束” |
| 自然/外部任务迁移 | 未完成 | 不可声称通用业务部署有效；模板合成基准定位仍可保留 |
| 新算法或新机制 | v6 无新编译架构、奖励机制或绑定算法 | 增加 split 与修评测漏洞本身不构成新的学习算法 |

字段裂缝是解释结论的硬边界。4B tool 的 strict/core F1 三 seed 分别为 .9324/.9361、.6788/.9701、.4428/.8004；struct 为 .7203/.9897、.5947/.9174、.5875/.9170。历史破坏性诊断改 scope/state/severity/evidence 后 72/72 faithful 不变。**v6 没有给这些字段增加行为谓词。** `evidence_exact_rate` 又只在 strict 匹配约束上计分，不能写成全量证据正确率。需要同时列 strict F1、core F1、record exact、证据的实际分母、faithful、safe 与 N 三通道，避免用一个接近满分的数字覆盖记录错误。

## 3. 必须在 GPU 上跑完的工作

以下“成功概率”是**获得完整、可分析证据的主观规划区间**，不是 CCF-B 录用概率，也不是已经校准的统计预测；对“正面科学结论”的估计单独写出。P0 是当前 v6 主线所需；P1 是保留相应扩展主张才需要。成本不重复累加共用步骤。

| 优先级 | 硬缺口与完成判据 | 预计成本 | 成功概率/主要不确定性 |
|---|---|---|---|
| P0 / G1 | 1.7B、4B 各完整 42/43/44；所有五个评估切分、seed42 同底座零样本、adapter、原始预测、source/data/model hash 与 completion 均齐全；不选最好 seed | 约 **22–25 GPU 小时**，单卡顺序；异常时按实际消耗停止 | 获得完整六 run 暂估 **70–85%**；服务器吞吐、token 门禁与 OOM 未实机验收。H1 方向维持的主观把握高于 H2，但是否满足每个注册区间仍待测 |
| P1 / G2 | 0.6B 三 seed；只有三尺寸 scaling/最小部署模型主张需要；若预算不够，明确该臂 incomplete，不能补一个 seed 代表均值 | 另约 **7–9 GPU 小时**；与 G1 合计可能超过 30 小时 | 在同一 30 小时 cap 内完成全九 run 暂估 **20–40%**。非核心论文可以省去该尺寸的确认性主张，不能省掉已声称的种子 |
| P1 / G3 | 若保留“跨自然表述/跨业务泛化”，在独立写成并先冻结的任务/人类改写上，用已训练 adapter 完整推理；同强基线接口，禁止错误后删题 | 预留约 **1–3 GPU 小时推理**，不新增训练；数据制作见 N4 | 取得可用测量约 **80–95%**；维持高性能仅暂估 **30–60%**。不确定性很高。当前九 run 队列未包含此臂；只能使用总预算内剩余时间，否则收窄主张 |

成本依据不是显存或模型大小猜算：六份已完成 v5 文件的 `train_seconds` 合计 **20.7596 小时**，其中 1.7B 8.425、4B 12.335。该字段计时从 main 开始到训练后评估结束，包含模型加载、seed42 零样本和评估，**不等于纯训练时长**。v6 多一个 1,050 条切分，因此用 22–25 小时作六 run 初步规划；这不是时限保证。

本次队列执行 G1 后再尝试 G2，且累计模型子进程时间上限 30 小时。当前 v5 的等待时间不计入新实验预算。若 30 小时将到，必须结束自己的 v6 任务并标记 incomplete，不能缩短到“够用的 epoch”充作完整 run。已有六 run 若完成，即使 0.6B 未完成也可以单独 CPU 汇总。

N1 必须使用已冻结的 [盲审协议](v6_human_review_protocol.md)：两人只能看模型实际可见的 prompt，不给 hidden witness/task graph。每个 cell 仅 5 条，错一条就是 80%；因此 cell 数值用于定位问题，不能估计精确总体流行率。协议主门禁按 strata observations 计率，重叠记录必须同时给 unique-record 分母，不得把重叠当独立样本增加置信度。人工标注是本项目保留语义主张所需的证据，不是“CCF-B 官方要求每篇论文必须双盲”的杜撰规定。

## 5. H2：v6 能救什么，不能救什么

**不能救冻结 v5 的 H2。** 4B tool 的实际成功总数是 `637+671+519=1827/2100=87%`。即使把 seed44 假设成满分，上界 `2008/2100=95.619%` 仍比 DeepSeek `698/700=99.714%` 低 4.095pp。实际 struct 是 `2032/2100=96.7619%`，比 DeepSeek `699/700=99.8571%` 低 3.0952pp，连均值点差也在界外。不能写“struct 已刚过”。

**可以检验一个新的 v6 H2，但目前没有支持其翻盘的实证机制。** v6 改了组合分布、增加新切分、修了主要影响 N 的 fail-open；这些改动没有直接修复 v5 tool 中的角色参数绑定与 seed 失稳。4B 三 seed 的 OOD JSON parse 和 query-state accuracy 都是 1，格式修复不能解释那 21.71pp 的 tool 极差。训练配方与模型不变，删除含隐私+授权组合还可能改变其他类型的支持分布。

保守资源决策上，**不把“v6 在所有预先命名切分都对 DeepSeek 达到 −3pp 非劣效”当作大概率事件；可按低于约 20% 的主观规划等级处理**。这个数字不是统计估计，六个旧 run 不足以给新分布校准成功概率。v6 DeepSeek 的表现也必须重新测，不能把 v5 的 99.x% 当成 v6 常数。

正确判定是：固定模型与 42/43/44，逐 split 对共同 task group 比较，保留 −3pp 门槛，要求指定的配对区间下界超过门槛；不能事后只保留最好 split、最好 seed 或降低 margin。三 seed 条件 bootstrap 不覆盖未来训练种子的总体风险。如果新 H2 仍失败，但 N1、N3、N4 证明了一个有用、可重复、与最近邻有明确区别的诊断问题，仍可形成负结果/benchmark 论文。

## 6. composition_ho 的 seed 方差：保守判断

**没有依据保证比 tool_ho 小。机制上有变小的理由，规划上应防守相当甚至更大。** 新切分复用 train 工具世界和措辞，消除了名称级绑定 OOD 的一部分难度；但它要求一次同时正确处理训练中从未共现的 privacy+tool_auth，两个约束的联合错误会放大模型差异。它只有一种正例 type set，没有别的较容易类型稀释失败。

目前的弱方向判断是“可能比纯工具名留出稳定一些”，置信度低；**不将它预估成 1–3pp 的稳定 SD**。预算/论文风险按旧 tool 的约 **10–12pp seed SD、约 20pp 极差量级**做压力情景，同时保留比这更大的失败尾部。这里是规划情景，不是新 split 的预测区间，更不是已测方差。350 个任务组只会影响任务采样误差，不能消除训练 seed 方差。

结果到齐后同时报告：privacy 单约束与 tool_auth 单约束的对应支持、pair 联合正确率、E/I 分列、角色参数错误、strict/core/faithful，以及三 seed 的失败样本重叠。单约束与 pair 的基数、约束条数和筛选分布不同，不能直接把它们的差称为组合的因果效应。一个 pair 也不能验证一般 compositional generalization。

## 7. 4.18 / 4.28 若要过 4.3，究竟缺什么

历史 4.3 是本地 CCFA 的 **accept-to-develop 概念阈值**，不是录用分、投稿线。原 rubric 明确把实验、消融和可复现完整性排除在概念默认评分外。故“再补六 run / 双标注 / 多一个 split 就加 0.02”不成立；历史聚合分也不足以反推每个维度要加多少。实验可以推翻或支撑机制判断、提高投稿准备度，但应在同一 rubric 下重新审查概念本身。

| 对象 | 需要改变/说清的概念 | 所需支持材料与证据 | 当前判断 |
|---|---|---|---|
| ② 历史 4.18 | 原奖励/信用分配为何解决已有方法未解决的问题；若改成交叉干预，则明确固定什么、替换什么、识别何种错误，和 oracle 上界的作用 | 与现成验证、重排、一次 repair、符号归一化的**同信息同预算**机制对照；把收益归因到可移除的核心机制，并用未参与构想的新任务验证 | 原 GRPO 三 seed 动作归因 +1/0/−1、预防性 0/+2/−2，不支持稳定正收益。v6 E1 队列不包含这类新算法实验，不能救原②。建议保留为分析/负结果，不继续拿历史 4.18 代表改版② |

## 8. 本轮工程交付与验收边界

入口为 [等待接力脚本](../scripts/wait_and_run_v6.sh)、[固定训练队列](../scripts/run_v6_queue.sh)、[PE 队列](../scripts/run_pe_v6.sh)；完整命令与恢复规则见[服务器交付说明](v6_server_handoff.md)。

已完成的行为：

- `run_e1_v6.py` 只接受 BF16 与注册模型/种子/完整训练参数；启动前检查单卡 BF16 和真实 tokenizer 全量覆盖，拒绝训练截断与 gold 超长。共享旧 trainer 的兼容参数不构成 v6 可用短训入口。
- 接力器轮询 `nvidia-smi` 与进程表；低于 5 GiB、无 GPU compute 进程、无识别到的 Python 训练进程，连续两次满足才启动 v6 queue。记录 UTC、GPU 名称/UUID；物理 GPU 锁跨本接力器实例共享。
- 先校验本地封存的 release SHA，再独立运行 verifier 并比对六个数据 SHA；重验报告写到新 outputs，避免改写数据报告。每个完整 model+seed 追加 manifest；完成标记绑定源码/模型/数据/环境及预测/adapter 哈希。
- 累计预算覆盖零样本、训练和评估的模型子进程；独立超时看门狗与持久化状态防止重启获得新 30 小时。预算到期标 incomplete；OOM/NaN/校验失败/非零退出停止后续队列，保留已完成和失败证据。
- PE 从环境读取 `DASHSCOPE_API_KEY`，只有缺失请求时才需要 key；完整且哈希匹配的缓存无需 key、零请求重用。破损、重复、跨配置缓存拒绝接纳。

没有实际训练，所以本地测试不能证明目标服务器驱动、Linux 锁、GNU timeout 与模型显存联动正常；首次目标机正式任务会经过门禁，失败即停。外部手工启动器若不遵守 GPU 锁，仍不能和该队列并行训练。

最终本地测试、数据重验、token 覆盖、冻结文件 SHA 对比及发布包摘要记录在 [本轮验证清单](_audit_work_20261124/task12_validation.json)。v5 冻结路径按任务开始时的 SHA 比对；不把仓库原有 dirty 文件误报成本轮修改。发布清单在全部代码/测试/设计修改后生成，服务器只核验，不重新封存。
