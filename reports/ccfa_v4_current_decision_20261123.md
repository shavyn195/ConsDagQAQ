# ConsDAG v4：CCFA 对照、实验证据与 CCF-B 距离

日期：2026-11-23

依据：`literature/ccfa_skills_v0.12.1` 的 `ccf-idea-reviewer`、`ccf-experiment-designer`、`evidence-design` 与 `experiment-discipline`，项目文献审计、v4 数据审计、E1/E2 原始结果和服务器日志。

## 结论

项目仍有 CCF-B 机会，但目前不能称为“稳稳够投”。可以继续形成一篇证据链完整的工作，最稳的论文口径是：

1. **① 训练式、可审计的逐请求约束编译器**：把用户请求编译成带类型、参数、表达状态、证据和作用角色的结构化对象；
2. **③ E/I/N 配对的可执行约束基准**：同一任务骨架上的显式表达、请求内可恢复的情境表达和受控无约束对照，配合构造期可行性与执行检查；
3. **② 失败来源交叉干预分析**：区分约束解释错误和候选计划搜索错误，说明约束编译器的输出何时能够救回候选计划。

原先的“外部锚门控、节点归因、非对称罚的 GRPO 已经稳定解决 reward hacking”没有被现有结果支持，不能继续作为已验证的第二个算法贡献。它应写成负结果、设计边界或交叉干预的动机，除非后续出现稳定、多种子、同预算的正向增益。

CCFA v0.12.1 的历史六维分数为：① 4.13、② 4.18、③ 4.28。按 rubric，三项均为 **revise**，不是 accept-to-develop。该分数只评概念，不等同于投稿准备度；下面的 CCF-B 判断另行给出。

## 1. 当前创新点与可守范围

### ① Evidence-bound constraint compiler

编译器独立于具体 planner，输入用户请求以及公开工具/策略目录，输出约束类型、参数、表达状态、原文证据片段和抽象工具角色。它的价值是把“请求理解错误”和“后续计划执行错误”拆成可审计的接口，并允许本机部署。

当前证据支持：在冻结的合成工具世界和 v4 输出契约下，LoRA 训练显著提高结构化约束抽取，并改善固定规划器上的 faithful execution；训练式小模型比同底座零样本稳定得多。当前证据不支持：

- 已证明 confidence 校准、拒判、severity、scope、evidence 每个字段都有独立的因果执行收益；
- 已全面优于强模型提示词；
- 已证明自然业务流量或人类读者对所有隐式约束有唯一共识。

因此 ① 的首创句式应是“训练式逐请求 typed 约束编译、可审计字段和执行验收的组合”，而不是“首次约束编译”或“首次隐式约束”。

### ② 约束解释与候选计划搜索的交叉干预

把固定候选计划空间中的两类变量分开：替换编译器输出，或替换候选计划/局部修复器，然后观察安全完成是否恢复。这个口径有直接结果支撑。

原 GRPO 口径不能作为成功算法：动作信用、预防动作和加权 SFT 的多种子结果没有稳定净增；在相同编译输出下，单纯给每条轨迹加同一个漏检常数还会被组内中心化抵消。现阶段应报告“约束解释与搜索失败可分离”，而不是“新奖励因子化已解决 hacking”。

### ③ Executable paired constraint benchmark

v4 每组保留同一任务骨架和约束集，生成 E（显式）、I（约束不直陈但有请求内情境线索）和 N（约束相关内容受控删除/干扰）三版。论文中必须写“(E,I) 等价对 + (N) 对比臂”，不能写“三版语义等价”。数据附 witness、逐条必要性检查、约束到工具角色绑定、执行检查器及措辞/工具名留出。

当前可以主张该组合在受控合成工具世界中可执行、可审计、有配对比较价值。还不能主张“人类天然可恢复”或“跨流程结构泛化已证明”：独立盲审结果尚未回收，工具名留出主要仍是名称级留出，流程阶段和拓扑大体同构。

## 2. 与相关工作的边界

下表只主张组合差异，不把已被先例覆盖的局部组件写成首创。

| 工作 | URL | 对方已覆盖 | ConsDAG 可守差异 |
|---|---|---|---|
| ATLAS | https://arxiv.org/abs/2509.25586 | 提示词多 agent、显式/隐式要求、scope | 训练专用小编译器、typed 参数、证据字段、执行级 E/I/N 配对 |
| CGAP | https://arxiv.org/abs/2610.41040 | 工具目录到操作/约束的编译、来源证据、运行时门控 | 逐请求用户约束的训练编译；其能力规则发现与本项目的 query 约束对象不同 |
| Sapien | https://arxiv.org/abs/2610.00797 | 从 prompt 合成可执行工具策略 | 不提供本项目的 typed 约束记录与 E/I/N 执行基准 |
| NOMOS | https://arxiv.org/abs/2610.11030 | 书面 policy 编译为运行时 gate、本机编译比较 | 域级 policy 与逐 query 约束对象不同；本机部署本身不是新颖性 |
| CARL | https://arxiv.org/abs/2607.04854 | planner 本体约束感知 RL/KL | 不物化独立约束对象，也没有本项目配对执行基准 |
| TAG | https://arxiv.org/abs/2610.21404 | 内部锚门控辅助信用 | 锚和信用来源设计不同，但本项目目前没有稳定训练增益，不能宣称优于 TAG |
| RLVP | https://arxiv.org/abs/2607.07435 | 结果奖励加逐动作可验证罚 | 其约束人工给定；本项目的自动发现仍是目标，但当前只证明交叉干预而非新 GRPO 成功 |
| SEVerA | https://arxiv.org/abs/2603.25111 | 形式合同、验证回退、硬/软分离 | 约束由形式规约给定，不处理逐请求自然语言约束发现 |
| DAGent | https://arxiv.org/abs/2609.39154 | DAG 拓扑级结果信用 | 对象是研究证据 DAG，不是用户约束编译和参数验收 |
| LogiSafetyBench | https://arxiv.org/abs/2601.08196 | 隐式法规合规、工具执行和时序验证 | 依赖法规/系统提示，非本项目的 query 级参数编译、N 对照和训练接口 |
| AM-Bench | https://arxiv.org/abs/2610.18090 | 同任务显式、模糊、缺失变体 | 缺失档不保证从请求恢复金标；本项目 I 档有请求内线索，N 是受控对比 |
| ExecutionFirst | https://arxiv.org/abs/2607.29175 | 同轨迹多档表达、执行优先验证 | 操纵执行细节明确度，不是约束表达状态和约束对象编译 |
| LIFT | https://arxiv.org/abs/2610.28819 | 合成、双渲染和大规模训练集 | 约束全显式，没有参数级 I 线索、N 干扰和逐条执行咬合的组合 |
| ToolPrivacyBench | https://arxiv.org/abs/2606.28061 | 工具调用隐私执行审计 | 可作外部 OOD 候选，但不是逐请求约束编译器基准 |
| Beyond ReAct | https://arxiv.org/abs/2511.10037 | Qwen3 工具 DAG planner 和合成工作流 | 只作为可信工具规划案例/下游环境，方法层不绑定该基座 |

建议论文用语：

> 据已核验的检索范围，尚未发现同时具备训练专用逐请求 typed 参数编译、请求内可恢复 I 线索、N 近似对照、逐条必要执行咬合和双留出切分的工作。

不要写“首次约束编译”“首次隐式约束”“首次 scope 绑定”，也不要把 77 篇扫描数量写成无人做过的证明。

## 3. 数据集审计

v4 冻结数据包含 **5,000 个任务组、15,000 条 E/I/N 样本**，训练/开发/措辞留出/工具名留出为 4,000/300/350/350 组，即 12,000/900/1,050/1,050 条。2026-11-23 再次运行 `src/verify_dataset_v4.py`，结果为：

- 15,000/15,000 构造记录通过；
- witness 达成任务且满足约束，逐条必要性检查无失败；
- query、task goal、group id 的跨切分重叠为 0；
- 证据、配对和泄漏检查无失败；
- 25 个关键数据/E1/侧实验回归测试通过。

这足以支持受控合成工具世界里的方法比较，但有三条边界：

1. 工具名留出主要是名称级留出，阶段数、候选位置、流程拓扑和数值分布仍相近，不能写成全面结构 OOD。
2. 公共策略卡对部分测试字段提供了映射，PII 别名结果应当作泄漏/敏感性诊断，不能作为纯 OOD 证明。
3. I 版尚无两名独立标注者的人类恢复率、N 空集误报率和一致性。作者中文试读是定性材料，不能替代独立人评。

## 4. 已完成实验与正确结论

### E1：编译器主表

主表使用冻结 v4 的 `faithful_success`：任务完成、满足金标约束并满足规定的最小改动条件。当前 seed42 结果为：

| 系统 | dev 600 | template holdout 700 | tool-name holdout 700 |
|---|---:|---:|---:|
| Qwen3-0.6B LoRA | 584 (97.33%) | 576 (82.29%) | 529 (75.57%) |
| Qwen3-1.7B LoRA | 600 (100.00%) | 670 (95.71%) | 567 (81.00%) |
| Qwen3-4B LoRA | 600 (100.00%) | 671 (95.86%) | 699 (99.86%) |
| Qwen-Max PE zero-shot | 543 (90.50%) | 612 (87.43%) | 608 (86.86%) |
| Qwen-Max PE ten-shot | 529 (88.17%) | 595 (85.00%) | 624 (89.14%) |
| DeepSeek PE ten-shot | 596 (99.33%) | 693 (99.00%) | 700 (100.00%) |

结论是：训练相对同底座零样本有明确收益；1.7B/4B 在合成世界接近强模型提示词；DeepSeek 在模板和工具留出上仍更强，不能写“训练模型全面超过强模型”。4B 工具名留出执行几乎满分，但含有效证据的完整记录只有 552/700，说明执行成功不能替代证据保真度。

解析级 F1、证据、scope、N 误报与执行指标必须分列。`e1_exec_v1`、旧版 `e1_score_v3` 和主表 `faithful_success` 不能混成一个分数。

### E2：交叉干预与局部修复

在 1,400 道受约束题上，初始候选重排安全完成 682，允许一次验证过的局部修复后为 1,144；逐题 464 胜、2 负，配对提升 33.00 个百分点，固定种子 bootstrap 区间约为 30.00–36.07。另一训练顺序为 756→1,199，合并两次固定顺序的配对提升为 32.32 个百分点，区间约为 29.61–35.11。

这说明约束解释失败与候选搜索失败可以在固定候选空间里被分开观察；它不证明 GRPO 奖励训练已经取得稳定提升。原动作信用、预防动作和加权 SFT 结果应作为负结果/边界分析，不能塞回正向主贡献。

### 效率与强模型对照

同卡、同一输入/输出长度、BF16、batch=1 的受控测量中，1.7B 纯解码中位 37.38 ms/token，4B 为 48.75 ms/token，1.7B 快 23.3%。峰值显存约 3.36 GiB 对 7.72 GiB。该结果支持小模型在自托管和延迟上的工程优势，但样本只有 10 个任务组，不能泛化到所有硬件、batch 或架构。

在 60 条研究侧 AI 新写措辞上，1.7B 完整记录 37/60，DeepSeek 十示例 59/60；仅历史/例子条件下，小模型误提约束 8/20，强模型 0/20。材料不是独立人类作者编写，不能把它当作人类泛化或准确率优势。

### 结构压力测试

已有小规模流程深度/缺失阶段压力测试：改变公开流程的必做阶段后安全完成从 70/80 降到 9/80，补回遗漏阶段后恢复到 70/80；另一批新阶段测试为 54→57/64，规范化符号对照为 64/64。这证明流程结构会影响搜索结果，但样本规模仍不足以承担全面结构泛化主张。

## 5. 代码和数值可靠性

`src/run_e1.py` 已包含：

- backward 前有限 loss 检查；
- 梯度范数裁剪，`error_if_nonfinite=True`；
- optimizer step 后 trainable 参数逐项有限性检查；
- 异常时写 `training_failure.json`，不保存适配器并直接失败；
- 结果写入模型、数据、代码哈希及完整运行配置。

因此 BF16 seed43 队列不会静默把 NaN 训练写成有效结果。旧的本地 FP16 NaN 运行只能作为失败记录，不能进入主表。

## 6. 距离 CCF-B 还差什么

### 必须补齐的硬缺口

1. **I/N 独立可恢复性**：至少两名独立标注者，或不参与构造的强模型，只看请求、目录和策略卡，恢复 type+params，允许回答“信息不足”；报告一致率、N 空集误报、争议样本和仲裁规则。
2. **训练随机性**：seed43 完成后，至少给 0.6B/1.7B 的逐 seed、均值和标准差。任务级 bootstrap 不能替代训练方差。
3. **结构泛化口径**：要么补一个流程拓扑/阶段结构不同且冻结的 OOD 子集，要么明确将结论限制为名称级合成工具世界，并把压力测试作为诊断而非泛化证明。
4. **② 的定位**：若按方法论文保留 GRPO，需有稳定正向增益、同预算多种子和完整消融；若不再投入，正式主线应收敛为 ①+③，②写成交叉干预分析。
5. **字段效用边界**：evidence、scope、confidence/拒判目前是审计接口；没有逐字段消费/消融时，不要声称它们各自带来下游收益。

### 已具备的投稿基础

- v4 数据、构造可行性、必要性和跨切分审计可复核；
- 同底座零样本、LoRA、Qwen-Max 和 DeepSeek PE 对照已完成；
- faithful execution、解析级指标、证据/作用范围诊断和失败案例齐全；
- 负结果、NaN 失败和旧版本污染已隔离；
- 服务器运行配置、数据哈希、代码哈希和原始输出均有记录。

## 最终判断

**①和③可以继续，且在“受控合成工具世界”范围内已经形成可辩护的论文主线；②原算法主张目前不成立，应降为交叉干预/失败分析，或另做有正收益的新机制。**

**现在距离 CCF-B 不是“只差写作”，而是还差独立 I/N 可恢复性、训练多 seed、结构 OOD 或明确收窄结论，以及②的最终定位。**

补齐前四项中的前三项后，投稿机会是现实的；不补时仍可能作为初步工程/基准工作投稿，但容易被批评为合成数据自证、名称级泛化和第二贡献未成立，不能说稳投或保证录用。
