# ConsDAG v4：CCFA 对照与 CCF-B 投稿准备度报告

日期：2026-11-22  
依据：`literature/ccfa_skills_v0.12.1` 的 idea-reviewer、experiment-designer、evidence-design、experiment-discipline；项目文献审计 `reports/literature_audit_v4.md`；v4 数据、代码和服务器结果。

## 结论先行

当前项目**还有机会投稿 CCF-B**，但还不能称为“稳稳够投”。最稳的论文形态是：

> 一个逐请求约束编译器（①）和一个带 E/I/N 配对、可执行验收的约束基准（③），并用交叉干预实验分析“约束解释失败”和“候选计划搜索失败”如何共同造成执行失败（②）。

这与最初的“约束锚定 GRPO 奖励分解已经解决 reward hacking”不同。现有结果不支持后一个强主张；继续把原 GRPO 作为成功方法会明显削弱投稿可信度。

按 CCFA 六维概念评分的历史结果：① 4.13、② 4.18、③ 4.28；三者都属于 `revise`（4.3 才是 `accept-to-develop`）。这不是投稿概率评分，实验完成度也不应倒灌到概念分数。结合当前实证，①和③是“可继续、需收窄”；②是“原方法主张应撤下，保留为实证分析”，因此不能把旧的 4.18 当作②当前方法已经成立的证明。

## 当前三个创新点

### ① 训练的、可审计的逐请求约束编译器

输入是用户请求和公开工具/策略目录，输出 typed 约束记录：约束类型、参数、表达状态、原文证据片段和适用工具角色。编译器独立于具体 planner，输出既可供执行器消费，也可逐字段审计。

可保留的主张是“在固定工具世界和公开契约下，训练小模型能稳定把请求编译成参数化约束，并改善后续 faithful execution”。不能再把以下内容当成已证明贡献：校准置信度、拒判、severity/scope/evidence 每个字段各自带来执行收益，以及全面胜过强模型 PE。

### ② 约束解释与候选计划搜索的交叉干预分析

固定任务、候选计划和编辑预算，分别替换约束编译器与候选计划产生器，统计哪些失败可由编译器修复、哪些失败只能由搜索空间修复，并计算候选空间的安全完成上限。这是当前数据真正支持的②。

原先的“外部锚门控 + 节点信用 + 非对称罚的 GRPO 新算法”没有得到稳定训练收益：三种子动作归因相对整轨迹奖励净增为 `+1/0/-1`，预防动作版本也没有稳定正收益。因此不能把原 GRPO 作为已验证的新奖励算法；若要保留它，应该明确写成负结果和设计边界。

### ③ E/I/N 配对的可执行约束基准

每个任务组包含同一任务和同一约束的显式表达 E、可由请求内情境线索恢复的表达 I，以及带近似干扰句的无约束 N。每组附可行 witness、逐条必要性检查、约束到角色标注、执行检查器、未见措辞和未见工具名切分。

可保留的组合是“参数级约束 + 请求内可恢复线索 + N 近似干扰 + 逐条必要 + 执行级 faithful 指标 + 训练集”。不能写“首个隐式约束工具基准”或“三版语义等价”；应写“(E,I) 等价对 + (N) 对比臂”。

## 与最近工作的边界

以下 URL 是本轮全文或抽节核验后的直接相关工作；差异是可守的组合差异，不是“所有局部组件都首次出现”。

| 工作 | URL | 已覆盖部分 | ConsDAG 可守的差异 |
|---|---|---|---|
| ATLAS | https://arxiv.org/abs/2509.25586 | 请求中的显式/隐式要求和 scope，主要是提示词多 agent | 训练专用小编译器、typed 参数、证据字段、执行级 E/I/N 配对 |
| CGAP | https://arxiv.org/abs/2610.41040 | 工具目录到操作/约束的提示词编译，带证据来源 | 逐请求用户约束的训练编译；CGAP 的约束对象无我方 typed 契约，且能力规则发现边界不同 |
| Sapien | https://arxiv.org/abs/2610.00797 | 逐 prompt 生成可执行工具策略 | 使用现成 LLM；不提供我方 typed 约束记录和参数级 E/I/N 基准 |
| NOMOS | https://arxiv.org/abs/2610.11030 | 书面 policy 编译为运行时 gate，并比较本机编译 | 域级 policy 编译不同于逐 query 约束对象；本机部署不能单独作为新颖性主张 |
| CARL | https://arxiv.org/abs/2607.04854 | planner 本体的约束感知 RL/KL | 不物化独立约束对象，也没有我方编译器与 E/I/N 执行基准 |
| TAG | https://arxiv.org/abs/2610.21404 | 内部锚门控辅助信用 | 我方原②的外部锚/编译输出差异仍是设计差异，但当前没有稳定训练增益，不能宣称优于 TAG |
| RLVP | https://arxiv.org/abs/2607.07435 | 结果奖励与逐动作可验证罚 | RLVP 约束人工给定；我方曾想解决自动发现，但现有结果只支持失败来源分析，不支持新 GRPO 成功 |
| SEVerA | https://arxiv.org/abs/2603.25111 | 形式合同、验证回退和硬/软分离 | 其约束是给定形式规约，不处理自然语言请求中的逐 query 约束发现 |
| DAGent | https://arxiv.org/abs/2609.39154 | DAG 拓扑级结果信用 | 对象是研究证据 DAG，不是用户约束编译和参数执行验收 |
| LogiSafetyBench | https://arxiv.org/abs/2601.08196 | 隐式合规、工具执行和形式时序预言，并有人工验证 | 对方隐式来源是系统提示法规全文，且自认不处理参数级约束；没有 N 近似干扰和我方训练集配对 |
| AM-Bench | https://arxiv.org/abs/2610.18090 | 同任务的显式/模糊/缺失变体 | 其缺失档可能无法从输入恢复金标；我方 I 档要求请求内线索可恢复，N 是受控对比臂 |
| ExecutionFirst | https://arxiv.org/abs/2607.29175 | 同一轨迹多档表达和执行优先验证 | 操纵执行细节明确度，不是约束表达状态，且校验器与生成过程耦合 |
| LIFT | https://arxiv.org/abs/2610.28819 | 合成、双渲染和训练集规模 | 约束全部显式；没有我方参数级 I 线索、N 干扰和执行咬合组合 |
| ToolPrivacyBench | https://arxiv.org/abs/2606.28061 | 工具调用隐私执行审计 | 适合作为外部 OOD/对照候选；不是从请求编译约束的训练基准 |
| Beyond ReAct | https://arxiv.org/abs/2511.10037 | Qwen3 小模型工具 DAG planner 和合成工作流 | ConsDAG 的方法层不绑定该基座；它只是可信工具规划案例和下游环境 |

因此，①和③的可辩护句式应是“据我们核验，尚未发现同时具备训练专用逐请求 typed 参数编译、请求内可恢复 I 线索、N 近似对照、逐条必要执行咬合和双留出切分的工作”，并附检索协议；不要写“首次做约束编译/首次隐式合规/首次 scope 绑定”。

## 数据集审计

v4 为 5,000 个任务组、15,000 条 E/I/N 样本：训练/开发/措辞留出/工具名留出为 4,000/300/350/350 组。全量验证通过，组、目标和请求跨切分无交集；15,000/15,000 witness 达成目标并满足约束；去掉单条约束后的逐条必要性复核通过；证据子串、隐式指令词、held-out 工具名和配对一致性检查通过。代码回归测试和侧实验测试均通过。

数据仍有三个实质边界：

1. 工具名留出只是名称级留出，任务世界的阶段数、备选位置、配对模式和数值区间与训练同构，不能称为结构泛化。
2. 策略卡直接列出部分测试字段短语，PII 字段映射存在提示泄漏；对应结果必须作为诊断，不能包装成纯 OOD。
3. I 版的可恢复性还没有独立人类一致率。当前作者试读是定性记录，不能替代两名独立标注者的恢复率、空集误读率和一致性。

因此数据集可以用于“受控合成工具世界中的方法比较”，不能据此声称自然业务请求、人类共识或跨流程结构泛化已经被证明。

## 当前实验设计与结果

### E1 编译器主表

统一 v4 数据、同一 prompt 契约、bf16、LoRA、同一服务器环境下，受约束 faithful success 如下（每格为正确数/分母）：

| 系统 | dev 600 | template holdout 700 | tool-name holdout 700 |
|---|---:|---:|---:|
| Qwen3-0.6B LoRA | 584 (97.33%) | 576 (82.29%) | 529 (75.57%) |
| Qwen3-1.7B LoRA | 600 (100.00%) | 670 (95.71%) | 567 (81.00%) |
| Qwen3-4B LoRA | 600 (100.00%) | 671 (95.86%) | 699 (99.86%) |
| Qwen-Max PE zero-shot | 543 (90.50%) | 612 (87.43%) | 608 (86.86%) |
| Qwen-Max PE ten-shot | 529 (88.17%) | 595 (85.00%) | 624 (89.14%) |
| DeepSeek PE ten-shot | 596 (99.33%) | 693 (99.00%) | 700 (100.00%) |

这些结果支持三点：同底座训练显著改善约束编译；1.7B/4B 在合成工具世界接近强模型 PE；强模型并未被全面击败，尤其 DeepSeek 在模板和工具留出上更强。论文应报告差值和配对区间，不写“训练模型全面优于强模型”。

解析级 strict/core F1、state、N 误报、证据和 scope 必须与 faithful execution 分列。4B tool-name holdout 的执行为 699/700，但包含原文证据的完整记录只有 552/700，说明执行成功不能替代证据保真度。

### 执行干预与②

在 1,400 道受约束题上，固定四候选并允许一次验证过的局部修复后，安全完成从 682 提到 1,144，配对提升 33.0 个百分点，bootstrap 区间约为 30.0–36.1；规范化符号规划器为 1,149。2×2 交叉替换表明，换编译器可救回一批候选空间中可达的失败，换候选规划器也可救回原空间不可达的失败。这个结果足以支持“解释错误和搜索错误是可分离的失败来源”，不足以支持“新的 GRPO 奖励已成功提升训练策略”。

### 部署效率

同卡固定输入/输出长度下，1.7B 的端到端生成中位耗时比 4B 低约 23.2%，峰值已分配显存约 3.36 GiB 对 7.72 GiB。该结果可以支持“较小本地编译器有部署和延迟优势”；不能在没有统一价目、并发、吞吐和服务费协议时声称普遍成本更低。

## 距离 CCF-B 的差距

### 已基本具备

- ①和③已经有清晰问题、可执行数据、同底座训练/零样本/强模型 PE 对照。
- v3 的 N 版捷径、约束不起作用、隐藏契约和执行级缺失已通过 v4 重建修正。
- 结果包含逐题原始输出、数据哈希、执行检查器、配对比较和失败分析，复现链比只有 F1 的 pilot 完整。
- 负结果被保留，当前没有把 NaN、旧 v2/v3 泄漏结果或 smoke 结果混入主表。

### 仍是投稿硬缺口

1. **人类/独立 oracle 可恢复性**：I 档必须有至少两名独立标注者或两个不参与构造的强模型，只看请求、目录和策略卡，恢复 type+params，并允许“信息不足”；报告一致率、N 空集误报和争议样本。没有这项，③只能声称“构造金标下的模型恢复”，不能声称自然隐式约束有效。
2. **结构 OOD**：补一个阶段结构、工具组合或流程拓扑不同的外部/新生成子集，或者把结论明确收窄为名称级 held-out。当前 tool-name holdout 不能承担结构泛化主张。
3. **②定位**：如果投方法论文，必须换成一个有稳定增益、可做组件消融的新机制并按同预算复测；如果保留当前结果，②只能作为失败来源分析/负结果，主贡献集中在①+③。
4. **统计重复**：seed43 正在运行；完成后至少给 0.6B/1.7B 的均值、标准差和逐 seed 结果。当前主表是单 seed 加任务级 bootstrap，不能把 bootstrap 当训练随机性。
5. **字段效用**：evidence、scope、confidence/拒判尚未各自证明会改变执行；应把它们列为可审计输出和后续实验，不把完整 schema 的所有字段都写成已验证收益。
6. **公平和可复现说明**：锁定 v4 数据哈希、prompt、模型版本、temperature、请求覆盖和 API 失败处理；PE 结果必须来自全新 v4 目录，不能混用旧 v2/v3 缓存。

## 最终判断

**有机会发 CCF-B，但当前还差关键证据，不能稳投。** 最小可行投稿路线是：

1. 让当前 seed43 复测完成并做三模型均值/方差汇总；
2. 完成 I/N 的独立恢复率和一致性；
3. 增加一个结构不同的 OOD 或明确把结论限定在名称级合成工具世界；
4. 把②改成交叉干预实证，原 GRPO 只作负结果，不再声称算法成功；
5. 统一生成最终表：解析级、faithful execution、N 不必要修改、证据/span、scope 和失败类型分列。

如果只完成第 1 项而不补第 2–4 项，论文可以写成有价值的合成环境初步研究，但仍容易被 CCF-B 审稿人以“隐式标签自证、结构同构 OOD、第二创新点无收益”拒稿。若第 2–4 项补齐，①+③作为主线、②作为机制分析，投稿机会是现实的；仍不能承诺录用。

服务器上的 seed43 复测仍在运行，结果不会被本报告中途结论覆盖。
