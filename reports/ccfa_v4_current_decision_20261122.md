# ConsDAG v4 当前投稿决策报告

日期：2026-11-22  
依据：`literature/ccfa_skills_v0.12.1` 的 idea-reviewer、experiment-designer、evidence-design 与 experiment-discipline；`reports/literature_audit_v4.md`、`reports/design_v4_ccfb.md`、`reports/design_v4_independent_recheck.md`；v4 数据、代码和已保存结果。

## 结论

项目仍有 CCF-B 机会，但现在不能写成“稳稳够投”。最稳的投稿形态是：

1. 训练式、可审计的逐请求约束编译器（①）；
2. E/I/N 配对的可执行约束基准（③）；
3. 通过交叉干预区分“约束解释失败”和“候选计划搜索失败”的实证分析（②的新口径）；
4. 原约束锚定 GRPO 作为负结果和设计边界，而不是已经成功的新奖励算法。

CCFA 六维概念分数的历史结果为：① 4.13、② 4.18、③ 4.28。按照 v0.12.1 的校准表，三项都属于 `revise`；概念分数不等于投稿准备度。当前实证使①和③可继续，但需要收窄主张；原②的奖励算法主张没有得到稳定收益，不能继续作为已验证方法写入主贡献。

## 当前创新点与可守范围

### ① 训练式约束编译器

给定用户请求和公开工具/策略目录，独立训练的小模型输出类型、参数、表达状态、证据片段和适用工具角色。它把请求级约束变成可审计对象，使抽取错误与计划执行错误可以分开评估。

当前可以主张：在固定的合成工具世界中，LoRA 训练显著改善类型/参数抽取和受约束执行；小模型可以提供可本机运行的结构化接口。不能主张：已证明置信度校准、拒判、severity、scope 或 evidence 各自带来执行收益；也不能主张全面优于强模型提示词。

### ② 约束解释与候选计划搜索的交叉干预

固定任务、候选计划和局部编辑预算，分别替换约束编译器和候选产生器，测量哪些失败能够由哪一侧救回，并计算固定候选空间中的安全完成上限。这是当前数据真正支持的②。

原“外部锚门控 + 节点信用 + 非对称罚的 GRPO”在已有动作归因、预防动作和训练顺序实验中没有稳定净增，因此不能声称已解决 reward hacking。若论文必须保留算法贡献，需要一个有区分度的奖励信号、完整同预算消融和多 seed 结果；否则把它写成失败分析和方法边界更可信。

### ③ E/I/N 配对可执行基准

每个任务组包含同一任务和同一约束的显式表达 E、请求内情境线索表达 I，以及带近似干扰句的无约束 N。每组有可行 witness、逐条必要性检查、约束到工具角色绑定、执行检查器、未见措辞和未见工具名切分。

可守的组合是“参数级约束 + 请求内可恢复线索 + N 近似对照 + 构造期可行性和逐条必要 + 执行级指标 + 双留出”。不能写“首个隐式约束工具基准”，也不能写“三版语义等价”；应写“(E,I) 等价对 + (N) 对比臂”。人类独立恢复率尚未完成，因此暂时只能说“构造金标下的隐式恢复”。

## 数据集审计

v4 有 5,000 个任务组、15,000 条 E/I/N 样本，切分为 train 12,000、dev 900、template holdout 1,050、tool-name holdout 1,050。`data/processed_v4/verification_report.json` 和 `outputs/dataset_audit/v4-all-pairs-recheck.json` 均为 PASS：witness 达成目标并满足约束，逐条必要性检查通过，跨切分 query/goal/group 无重叠，配对和证据检查通过。本地相关回归测试也已通过。

数据可以支撑“受控合成工具世界中的方法比较”，但有三项边界：

- tool holdout 主要是工具名称和属性留出，阶段数、备选位置、数值区间和流程结构仍同构，不能称为结构泛化；
- 策略卡给出了部分测试字段映射，PII 别名相关结果应作为泄漏诊断，不作为纯 OOD 证明；
- I 版还没有至少两名独立标注者的人类恢复率、N 空集误报率和一致性，不能把模型恢复金标直接写成人类自然可恢复。

## 已完成实验及正确解读

主表采用冻结 v4 上的 **faithful_success**：计划完成、满足金标约束，并达到金标最小改动要求。当前已保存结果为：

| 系统 | dev | template holdout | tool-name holdout |
|---|---:|---:|---:|
| Qwen3-0.6B LoRA | 584/600 (97.33%) | 576/700 (82.29%) | 529/700 (75.57%) |
| Qwen3-1.7B LoRA | 600/600 (100.00%) | 670/700 (95.71%) | 567/700 (81.00%) |
| Qwen3-4B LoRA | 600/600 (100.00%) | 671/700 (95.86%) | 699/700 (99.86%) |
| Qwen-Max PE zero-shot | 543/600 (90.50%) | 612/700 (87.43%) | 608/700 (86.86%) |
| Qwen-Max PE ten-shot | 529/600 (88.17%) | 595/700 (85.00%) | 624/700 (89.14%) |
| DeepSeek PE ten-shot | 596/600 (99.33%) | 693/700 (99.00%) | 700/700 (100.00%) |

这些结果支持：

- 训练式编译器相对同底座 zero-shot 有明确收益；
- 1.7B/4B 在该合成世界接近强模型提示词，但没有全面超过 DeepSeek；
- 0.6B/1.7B 的本机部署、显存和延迟优势是可测的工程轴；
- 4B tool holdout 的执行几乎满分，但含有效 evidence 的完整记录只有 552/700，执行成功不能替代证据保真度。

注意：`metrics.json` 中的 `e1_exec_v1 safe_success` 和 `e1_score_v5/core F1` 是更宽的原始诊断口径，不能与上表 faithful_success 混报。论文主表必须固定一种口径，并同时列出解析级 F1、证据、scope、N 误报和执行指标。

② 的交叉干预实验在 1,400 道受约束题上将安全完成从 682 提到 1,144，配对提升约 33.0 个百分点，说明约束解释和候选搜索存在可分离的失败来源；但原 GRPO 训练臂没有稳定净增，不能由此推出新的奖励算法成功。

## 距离 CCF-B 的差距

### 已具备

- ①和③的问题、数据对象、执行检查和对照边界清楚；
- v4 已修复旧版 N 捷径、约束不起作用和跨 split 泄漏问题；
- 有强模型 PE、同底座 zero-shot/LoRA、执行级和解析级结果；
- 负结果和历史污染结果已隔离，没有把旧 v2/v3 数字放进主表。

### 仍是硬缺口

1. **I/N 独立可恢复性**：至少两名独立标注者或不参与构造的强模型，只看请求、目录和策略卡，恢复 type+params，允许回答“信息不足”；报告一致率、N 空集误报和争议样本。
2. **结构 OOD**：补阶段结构、工具组合或流程拓扑不同的外部/新生成子集；如果不补，结论明确限定为名称级留出。
3. **②定位**：若按方法论文投稿，需一个有稳定收益的新机制、同预算消融和多 seed；否则按“失败来源交叉干预分析”写，主贡献集中在①+③。
4. **训练随机性**：seed43 复测完成后给 0.6B/1.7B 至少均值、标准差和逐 seed；单 seed 加任务 bootstrap 不能替代训练方差。
5. **字段效用**：evidence、scope、confidence/拒判目前是可审计输出，不是已经被单独证明的因果收益；需消费这些字段的下游或受控字段消融。
6. **主表可复现性**：锁定 v4 数据哈希、prompt、模型版本、temperature、请求覆盖、失败处理和 scoring 版本，删除旧目录缓存混用可能。

## 当前机会判断

有机会发 CCF-B，条件是把论文收窄为“训练式约束编译 + 配对可执行基准 + 失败来源分析”，并完成上面第 1–4 项中的至少前三项。只等 seed43 而不补独立可恢复性、结构 OOD 和②定位，仍容易被认为是自证式合成数据、名称级泛化和未成立的第二方法贡献。补齐后，证据链达到可以认真投稿的水平，但仍不能承诺录用。

服务器为 RTX 4080 SUPER 32GB。2026-11-22 检查时，`Qwen3-1.7B-v4-seed43` 使用 BF16 正在训练，GPU 利用率约 61%，PID 100368；后续队列等待该任务结束后串行运行 0.6B seed43 和 4B seed43。当前没有新 seed43 指标，旧主表不被本轮复测覆盖。

下一步按优先级执行：

1. 保持 seed43 队列运行并在每个 `metrics.json` 生成后做哈希、配置和 scoring 版本核验；
2. 冻结 I/N 人工/独立 oracle 盲审材料，不用模型答对率筛选主测试集；
3. 生成结构不同的 OOD 小子集并复用同一执行检查器；
4. 汇总最终 E1 表，再决定是否投入新的②训练机制实验；
5. 只在②出现可辨学习信号时再开多 seed GRPO，避免继续消耗 GPU 做无区分度长跑。
