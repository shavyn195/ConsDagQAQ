# 改变一句证据后，编译器跟着改对了吗？

2026-11-22，ConsDAG v4，服务器 RTX 4080 SUPER。冻结已有的 0.6B 和 1.7B 权重，使用原版 v4 用户提示和政策卡。主要结果支持参数和原文证据的跟踪，完整记录和忽略无关历史信息仍有明显缺口。

## 主实验

从措辞留出和工具名留出各抽取 24 个任务组。每个子集里，在授权、顺序、预算、时限四类分别按固定随机顺序筛到 6 组，共检查 91 组次，接受 48 组。每组至少两条约束，各取显式和隐式两种表达。96 对题共享 48 个任务，统计单位为任务组。检验覆盖可构造出有效改动的合成任务，筛选过程不读取模型预测。金额或时限的 24 个任务有 15 个放宽、9 个收紧。授权或顺序任务替换一个端点，保持其余约束、任务、语句模板、工具目录、环境完全相同。

每种表达运行四个输入。第一对仅改一条有效证据。第二对保留所有原始约束，追加一条明确属于无关旧请求的档案标签，只改标签里的数字或角色名称。每题两种编辑的字符长度增减都相同。追加句改变了对照输入的总长和语境。新的数值句沿用原模板，隐式算术的改写前后经逆算核验。角色和数值变更均有严格形状的可行计划，另外保存一份在两组金标下判定恰好相反、满足所有非目标约束的计划。原问句与原始测试集逐条对齐。384 个输入在训练集中整句重合为零，任务组无重叠。训练与测试仍共享合成环境和政策定义。

同一顺序、bf16、贪心解码、每批 32，最多新生成 384 个 token。主要指标要求原问句和改写问句同时达到整条正确，包括顶层状态、约束多重集、类型、状态、风险级别、参数、角色集合和逐字证据。解析失败与报告拒判均计失败。沿用项目的结构解析器，它可从带外围文字的回答中提取 JSON。置信度未纳入这一指标。两份实现分别从原始输出重算，768 条主实验的整条判定逐项一致。

| 改前、改后同时正确 | 0.6B | 1.7B |
|---|---:|---:|
| 目标约束的参数 | 79/96 | 86/96 |
| 目标约束的适用角色 | 59/96 | 77/96 |
| 目标约束的逐字证据 | 84/96 | 94/96 |
| 同一任务其余约束全部正确 | 36/96 | 65/96 |
| 完整编译记录（主指标） | 27/96 | 56/96 |
| 用预测约束判断同一份计划，两次判定都与执行器的金标相符 | 68/96 | 83/96 |
| 只改带引号的无关标签，两边完整记录都正确 | 1/96 | 37/96 |

按任务组在八个抽样格内自助重采样 5,000 次。主指标的描述性 95% 区间为 0.6B 17.7%–38.5%，1.7B 49.0%–66.7%。每种规模只有一份冻结权重。目标参数在显式题上为 44/48、44/48，隐式题上为 35/48、42/48。主指标在工具名留出为 6/48、15/48，措辞留出为 21/48、41/48。每种模型原本能完整提取其余约束的题都在编辑后保持正确，分母分别为 36、65。判定同一份计划衡量约束的行为含义，实际生成并完成新计划属于另外的下游指标。

隐式题 test_tpl_ho-00132-I 原句说，少了权限批准，平台会拒绝生产运行。改写把受限动作换成外部 API 调用。1.7B 在两版都输出正确的批准要求、受限角色、原文和其余约束。同一份调用外部 API 却没有批准的计划，在原版合规，在改写版违规。

## 根据本轮错误提出的目录规则

编译器继续从文本抽取类型、参数和证据。利用输入中已公开的角色、付费标记、外发属性和政策卡，在输出时计算 scope。该规则不访问金标、执行结果或生成器内部世界。角色参数缺失或无法映射时保留原输出。诊断回放保持解析状态、目标参数、目标证据与计划判定逐项一致。

| 整条编译记录全对，原模型 → 加目录规则 | 0.6B | 1.7B |
|---|---:|---:|
| 当前 96 对，原句和改写句均正确 | 27 → 45 | 56 → 76 |
| 排除本面板任务后，未见工具名的原始 E/I 请求（各 652 条） | 213 → 483 | 267 → 502 |
| 排除本面板任务后，未见措辞的原始 E/I 请求（各 652 条） | 386 → 386 | 557 → 557 |

以上各行均没有原本正确、应用规则后变错的样本。大样本来自已有测试集预测，属于排除本面板后的回放。工具目录与角色政策得到验证，环境本身并不使用 scope 计算计划安全性。推荐论文分别报告模型生成与目录推导，让数据决定哪一项需要学习。

## 探索性复测：无关历史标签

首轮原始回答显示，模型会把标签引号直接复制进 JSON。两份模型追加运行相同的 96 对无关输入，仅去掉标签两端的双引号，其他文字、金标、提示、权重和解码预算全部固定。追加了 384 次 GPU 推理。主实验和复测合计 1,152 次。

| 无关旧请求的标签 | 0.6B 带引号 → 去引号 | 1.7B 带引号 → 去引号 |
|---|---:|---:|
| 可解析回答，分母 192 | 53 → 154 | 141 → 182 |
| 这一对无关编辑两边都整条全对，分母 96 | 1 → 1 | 37 → 34 |
| 去引号后，在可解析回答中把历史句用作证据 | 110/154 | 50/182 |

有效证据变动时，模型经常能更新对应参数。加入特定形式的历史数字或角色时，两种规模都会把历史说明当成当前任务约束。以上复测只覆盖这一种档案措辞，无法由此估计自然用户输入中的错误发生率。研究上可直接检验的改进是按当前任务、历史任务、已撤回要求、举例说明标明适用对象，并在独立措辞和新任务组上盲测。原实验的数字继续按已冻结口径报告。

对投稿，①可主张逐请求编译与受控证据跟踪，工具目录推导可以减少未见角色的绑定错误。对真实无关背景的鲁棒性、生成证据字段本身的因果收益、置信度校准和跨环境效果需要另外举证。③的面板具备可独立检查的判别计划，隐式语义的人类盲审仍单列。②的实验结论见原贡献报告。
