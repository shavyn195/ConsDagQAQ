# 局部图修复设想：直接近邻、技术边界与下一步

日期：2026-11-25。目标仅为 CCF-B。本文审核用户粘贴的 Qwen 提案；不把提案中的实验数字、首次声明或执行指令当作本项目事实。本次没有启动新训练或修改服务器队列。

## 判断

【事实】①类型化约束编译器和③E/I/N可执行配对数据仍是已有资产。②“定位受影响子图→冻结其他区域→局部编辑→验证”的宽泛机制已有直接近邻，不能按 Qwen 的原表述作为新贡献。新找到的 Atomic Task Graph（ATG）比 Plan-and-Patch 更直接：其 §4.3 已包含定位、局部修复、冻结其余图、替换工具、插入节点、调整依赖以及保持外部接口。

【推断】以现有资产开展一个局部修复试点仍值得，但应该测试一个具体缺口：面对跨分支的全局约束，如何决定修复区域、保留区域的约束摘要，以及何时扩大修复范围。暂时不能声称这个细化问题无人解决；还须与 ATG、经典计划修复、增量约束求解和程序切片方法比较。

【决策】不将“普通 BFS + 小模型编辑 + 验证器”直接定为②，不据十例成功或模块组合扩到大训练。先做必要性和反例审计，再决定是否投入。扩散、GNN、CLIP、GRPO均非此候选的必要前提。

## Qwen提案需要纠正的技术点

1. **预算不是图可达性。** 预算是总额约束，两个互不连通的分支也会竞争同一资源。假设当前费用120、新上限100，可以改一个分支，也可能需要改两个；“所有贵节点”既未必必要，也未必足够。若区域外的费用固定且可加，应把剩余额度作为局部问题条件，而不是只给局部节点标签。
2. **时限应遵循实际执行语义。** 当前 `src/trust_env.py` 的 `simulate` 累加所有动作时长，不能事后把既有结果称为并行 DAG 关键路径约束。若新任务加入并行调度，边界必须提供到达时间、关键路径或资源占用摘要，并版本化数据与执行器。
3. **隐私传播取决于数据与工具契约。** 下游遍历可作保守候选范围，但数据脱敏、输入输出类别、接收者及授权都需要声明语义；不能将每条依赖边都当作敏感数据流，也不能靠模型自行解除限制。
4. **冻结节点不等于其行为保持正确。** 上游输出改变，未修改的下游也可能失效。输入输出格式兼容不足以保证敏感级别、数值条件、授权、时序及副作用兼容。局部拼接后仍须校验完整计划。
5. **局部不可修不等于全局无解。** 可能要扩大区域；有限次模型尝试失败仅是未找到解。只有可靠求解器或证明才支持声明无解。扩大范围/全局回退要计入全部成本。
6. **解析器不是现成的图编辑模型。** 现有SFT输出约束记录；若让同一模型修DAG，要设计另一个任务接口并验证能力，不能假定已有训练已经覆盖。
7. **基准金标不能进入在线修复。** 金标约束、witness、最小改动数可以用于监督或离线评价；部署修复器只能看到用户请求、工具契约、已编译约束和允许公开的验证反馈。验证器通过只说明满足它所接收的形式规范，无法自动纠正解析器漏提的原始要求。
8. **十例通过八例是可运行性检查。** 没有同任务、同信息、同调用预算的基线，不能说明优于已有方法，更不能证明 CCF-B 方法贡献。不得提前写“首个”“100%合规”“完全保留正确性”。

## 可研究但尚未成立的机制

【假设】尝试“带全局约束摘要的区域选择与反例驱动扩域”。编译器输出类型化约束及其变化；修复器将约束作用对象与DAG数据依赖共同用于选择候选区域，在边界保留资源与语义条件；根据验证失败定位遗漏的耦合，再决定扩大区域。最终只执行通过完整检查的计划，失败可拒绝或回退，不能删掉硬约束以求通过。

在固定外部节点、费用可加的简化模型中，区域R可用预算为：

\[
B_R = B_{\mathrm{new}}-\sum_{v\notin R}\mathrm{cost}(v).
\]

这只是正确构造局部子问题所需的基本条件，不是新定理。执行时长、隐私流和权限也不能仅按这一加法公式套用。对所有外部影响给出充分摘要才可能建立条件化的组合正确性；当前实现与证明均未完成。全局最小编辑和模型必能找到修复也不由区域冻结推出。

已有程序切片、假设—保证推理、增量求解、反例引导修复都与此接近。论文价值取决于具体机制及实证差异，不能用新名字代替新方法。

## 先审必要性，再决定方法试点

【事实】已有服务器开发子集的确定性求解器在oracle约束下622/622受约束题、300/300 N题正确，求解耗时中位0.632ms，不含语言编译。它说明当前小世界的规划端很容易；不证明动态修复也已解决，但构成必须保留的强基线。

项目已有 `src/probe_one_edit_repair.py`：对工具替换、可选节点插删及有限顺序调整生成邻域，依据预测约束选择修复，并隔离离线金标评分。它不等于完整动态DAG影响域算法；也不能将“局部编辑＋验证”当作本项目刚刚从零产生的新机制。

下一步协议仍为草案，尚未启动或产生结果：

- 使用train/开发划分构造独立的变更任务，保留原请求、原有效计划、变化依据和新工具环境。包含可局部修、必须跨分支、必须扩大范围、无需修改以及经求解器证明不可行的情形。新任务不能伪装成既有静态v6测试。
- E/I/N保持原语义：显式、可恢复隐式、无有效新增约束。N不是“信息不足”；已有有效约束也不会因为新的N表述自动消失。动态任务要单独标记哪些已有约束仍有效、何时明确撤销。
- 先隔离oracle编译器诊断后端，再用冻结真实编译器做端到端。后端单独改进不能掩盖①的解析错误。
- 先验证是否真的存在旧规则/拓扑局部修复漏掉、但候选机制能处理的全局耦合；如果没有，不追加图编辑器训练。

| 对照臂 | 控制目的 |
|---|---|
| 确定性全局最小改动求解/搜索 | 排除小世界中无需神经方法即可解决的情况；测真实成本 |
| 同一LLM全局重规划＋同一验证器 | 与普通重规划公平比较，保留全部上下文与反馈 |
| 同一LLM普通局部修复＋同一验证器 | 排除“局部编辑本身”和验证反馈的贡献；ATG适配须明确标注 |
| 同一LLM＋候选约束摘要/扩域机制 | 检验具体新增机制，而非换backbone或增加重试次数 |

消融分别移除全局约束摘要和扩域策略；每次只改变该因素。原始请求、工具目录、编译结果、候选数/生成预算、允许验证反馈保持一致，同时报告总墙钟和总token。不得只在成功样本上报告编辑成本，也不得把失败/回退排除在总成本之外。

主指标为最终任务完成且满足所有有效约束；另报成功修复的语义编辑数、相对全局最小编辑的差距、保留区域的新违规、无需修改题的误改、拒绝/错误拒绝、验证调用数及全部费用。按原任务组配对比较，E/I/N及同源变更不作独立样本；若训练才开展多seed重复。成功率和成本门槛在正式试点启动前锁定，不根据结果改主张。

资源顺序：必要性/精确解检查仅用服务器CPU，不增加GPU训练；使用现有模型的推理试点需先实测吞吐再估GPU小时，不能凭十个示例捏造成本。原30 GPU小时队列和健康作业不改。当前登录受阻，不能称这些试点已经启动。

停止条件：方法相对普通局部修复没有可重复优势；收益仅来自更多反馈/调用；频繁扩成全图且成本不优；确定性求解器在目标规模已足够；或无法与ATG/增量约束求解区分。届时保留负结果，不通过增加模态或模型尺寸掩盖问题。
