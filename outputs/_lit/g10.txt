15:Abstract
16:Developing autonomous LLM agents capable of making a series of intelligent decisions to solve
17:complex, real-world tasks is a fast-evolving frontier. Like human cognitive development, agents
18:are expected to acquire knowledge and skills through exploration and interaction with the
19:environment. Despite advances, the community still lacks a unified, interactive reinforcement
20:learning (RL) framework that can effectively train such agents from scratch—without relying
21:on supervised fine-tuning (SFT)—across diverse and realistic environments. To bridge this gap,
22:we introduce AgentGym-RL, a new framework to train LLM agents for multi-turn interactive
23:decision-making through RL. The framework features a modular and decoupled architecture,
24:ensuring high flexibility and extensibility. It encompasses a wide variety of real-world scenarios,
25:and supports mainstream RL algorithms. Furthermore, we propose ScalingInter-RL, a training
26:approach designed for exploration-exploitation balance and stable RL optimization. In early
27:stages, it emphasizes exploitation by restricting the number of interaction, and gradually shifts
28:towards exploration with larger horizons to encourage diverse problem-solving strategies. In
29:this way, the agent develops more diverse behaviors and is less prone to collapse under long
30:horizons. We perform extensive experiments to validate the stability and effectiveness of both the
31:AgentGym-RL framework and ScalingInter-RL approach. Our agents match or surpass commercial
32:models on 27 tasks across diverse environments. We offer key insights and will open-source
33:complete AgentGym-RL framework—including code and datasets—to empower the research
34:community in developing the next generation of intelligent agents.

14:ABSTRACT
15:While large language models (LLMs) have demonstrated impressive performance
16:across tasks in language understanding and interactive decision making, their
17:abilities for reasoning (e.g. chain-of-thought prompting) and acting (e.g. action
18:plan generation) have primarily been studied as separate topics. In this paper, we
19:explore the use of LLMs to generate both reasoning traces and task-specific actions
20:in an interleaved manner, allowing for greater synergy between the two: reasoning
21:traces help the model induce, track, and update action plans as well as handle
22:exceptions, while actions allow it to interface with and gather additional information
23:from external sources such as knowledge bases or environments. We apply our
24:approach, named ReAct, to a diverse set of language and decision making tasks
25:and demonstrate its effectiveness over state-of-the-art baselines in addition to
26:improved human interpretability and trustworthiness. Concretely, on question
27:answering (HotpotQA) and fact verification (Fever), ReAct overcomes prevalent
28:issues of hallucination and error propagation in chain-of-thought reasoning by
29:interacting with a simple Wikipedia API, and generating human-like task-solving
30:trajectories that are more interpretable than baselines without reasoning traces.
31:Furthermore, on two interactive decision making benchmarks (ALFWorld and
32:WebShop), ReAct outperforms imitation and reinforcement learning methods by
33:an absolute success rate of 34% and 10% respectively, while being prompted with
34:only one or two in-context examples.

714:On the value of internal reasoning vs. external feedback
715:To our knowledge, ReAct is the first
716:demonstration of combined reasoning and action using an LLM applied to an interactive environment
717:within a closed-loop system. Perhaps the closest prior work is Inner Monologue (IM), from Huang
718:et al. (2022b), in which actions from an embodied agent are motivated by an eponymous “inner
719:monologue”. However, IM’s “inner monologue” is limited to observations of the environment
720:state and what needs to be completed by the agent for the goal to be satisfied. In contrast, the
721:reasoning traces in ReAct for decision making is flexible and sparse, allowing diverse reasoning
722:types (see Section 2) to be induced for different tasks.

18:We introduce rStar2-Agent, a 14B math reasoning model trained with agentic reinforcement learn-
19:ing to achieve frontier-level performance. Beyond current long CoT, the model demonstrates
20:advanced cognitive behaviors, such as thinking carefully before using Python coding tools and

23:makes agentic RL effective at scale: (i) an efficient RL infrastructure with a reliable Python code

837:To ensure reliable RL supervision, we follow two rules when collecting math problems. First, problems must be
838:high-quality, challenging, and have correctly labeled final answers. Second, answers must be integers. The integer-
839:only requirement is is essential because verifying equivalence between different algebraic expressions is notoriously
840:difficult. For example, current rule-based verifiers such as Prime and math verifier struggle to recognize that
841:(a+b)(b+c)(c+a) and (a+c)(c+b)(b+a) represent the same solution. Such cases can lead to incorrect rewards
842:by misclassifying correct rollouts as incorrect. Therefore, we only include math problems with integer answers.
843:Guided by these rules, we collect over 100K candidate problems from three sources. First, we include 17K integer-
844:only problems from the DAPO training set [Yu et al., 2025]. Next, we add 93K problems from the Art of Problem
845:Solving (AoPS) forums via OpenMathReasoning [Moshkov et al., 2025]. Finally, we include 937 challenging prob-
846:lems from Project Euler [Huggingface], which require both mathematical insight and programming skills.
847:We then perform extensive cleaning to produce a final set of 42K high-quality problem-answer pairs. For the Open-
848:MathReasoning dataset, we remove unverifiable answers (e.g., The limit does not exist), overly complex

1455:Conclusion
1456:This work introduces rStar2-Agent, a 14B math reasoning model that “ thinks smarter than merely longer”, achieving
1457:performance comparable to the 671B DeepSeek-R1 through large-scale agentic reinforcement learning. Its success
1458:is driven by the GRPO-RoC algorithm for effective training in a code environment, a scalable RL infrastructure,
1459:and a compute-efficient training recipe. Extensive experiments on two base model sizes demonstrate the superiority
1460:of the rStar2-Agent approach, with the 14B model reaching a pass@1 accuracy of 80.6% on AIME24 and 69.8%
1461:on AIME25, surpassing DeepSeek-R1 while producing shorter responses and generalizing beyond mathematics.

1464:environments. The code, datasets and recipes are publicly released to support further research and collaboration.

366:Method
367:Supervised fine-tuning (SFT), as illustrated in Fig-
368:ure 1, often suffers from overfitting to certain pat-
369:terns and constrains the model’s ability to learn
370:optimal strategies for tool use. To address this, we
371:introduce a reinforcement learning (RL) approach
372:for enhancing tool-integrated reasoning (TIR) in
373:LLMs. In this section, we begin by defining the
374:TIR task (Section 3.1), followed by our customized
375:rollout strategy (Section 3.2) and reward design
376:(Section 3.3). These components are then inte-
377:grated into the Group Relative Policy Optimization
378:(GRPO) framework (Shao et al., 2024) to guide
379:model training on general TIR tasks (Section 3.4).
380:3.1
381:Task Definition
382:Tool-Integrated Reasoning (TIR) is the process of
383:incorporating external tools into the reasoning tra-
384:jectory of an LLM to solve a user task. A typical
385:TIR trajectory involves multiple tool invocations
386:over several reasoning steps, with the final outcome
387:determined by the cumulative success of these in-
388:termediate decisions.
389:Formally, given a tool set T = {t1, t2, . . . , tn}
390:containing n available tools, and a user query Q,
391:the reasoning trajectory up to step k is denoted as:
392:sk = (r1, T1, o1) , (r2, T2, o2) , . . . , (rk, Tk, ok) ,
393:where ri denotes the model’s natural language rea-
394:soning at step i, Ti ⊆T denotes the set of tool
395:calls invoked at step i, and oi denotes the observa-
396:tion received after executing tools in Ti, possibly
397:including both environment and user feedback.
398:At each step k + 1, the model must generate
399:the next reasoning step rk+1, select a set of tools
400:Tk+1 ⊆T , and formulate a grounded tool call (i.e.,
401:a parameterized invocation of each tool) to make
402:progress toward solving Q.

696:of Hammer with randomized tool and parameter

698:rather than memorized labels, thus enhancing
699:generalization and reducing overfitting to certain
700:tools.
701:• xLAM (Zhang et al., 2024): A compositional
702:dataset requiring one or multiple tool calls per
703:turn, encouraging the model to reason about tool
704:dependencies and plan diverse tool calling action
705:actively.

707:ToolACE and 1K each from Hammer and xLAM,
708:creating a balanced dataset spanning diverse levels
709:of complexity and tool use. Multi-step trajectories
