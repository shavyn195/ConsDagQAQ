30:ABSTRACT
31:Large language models (LLMs) are increasingly expected to tackle complex tasks, driven
32:by their expanding applications and users’ growing proficiency in crafting sophisticated
33:prompts. However, as the number of explicitly stated requirements increases (particularly
34:more than 10 constraints), LLMs often struggle to accurately follow such complex instruc-
35:tions, which limits their applicability in complex real-world scenarios. To the best of our
36:knowledge, existing datasets do not exceed 10 constraints per instance. To address this chal-
37:lenge, we propose RECAST, an efficient and scalable framework for synthesizing datasets
38:where each example incorporates far more constraints than those in existing benchmarks,
39:aiming to challenge and extend the boundaries of models’ ability to follow complex in-
40:structions. These constraints are extracted from real-world prompt-response pairs to ensure
41:practical relevance. Using this framework, we construct RECAST-30K, a large-scale, high-
42:quality dataset comprising 30k instances spanning 19 constraint types. Experimental results
43:demonstrate that models fine-tuned on RECAST-30K substantially improve in following
44:complex instructions while maintaining their general capabilities without degradation.
45:Moreover, RECAST enables automatic verification of constraint satisfaction via rule-based
46:validators for quantitative constraints and LLM-based validators for qualitative ones, the
47:verifiability provided by RECAST enables the design of reward functions for reinforcement
48:learning, which further boosts model performance on complex and challenging tasks. Code
49:and data are available at https://github.com/Thekey756/RECAST.

1822:CONCLUSION
1823:We present RECAST, a scalable, low-cost framework for constructing complex instruction-following datasets through
1824:systematic mining and verification of rule- and model-based constraints. Using this, we release RECAST-30K, enabling
1825:smaller models (e.g., Llama3.1-8B) to outperform larger instruct-tuned models. Leveraging constraint verifiability, we

12:ABSTRACT
13:Agentic language models operate in a fundamentally different safety regime than
14:chat models: they must plan, call tools, and execute long-horizon actions where a
15:single misstep, such as accessing files or entering credentials, can cause irreversible
16:harm. Existing alignment methods, largely optimized for static generation and
17:task completion, break down in these settings due to sequential decision-making,
18:adversarial tool feedback, and overconfident intermediate reasoning. We introduce
19:MOSAIC, a post-training framework that aligns agents for safe multi-step tool use
20:by making safety decisions explicit and learnable. MOSAIC structures inference as
21:a plan, check, then act or refuse loop, with explicit safety reasoning and refusal as
22:first-class actions. To train without trajectory-level labels, we use preference-based
23:reinforcement learning with pairwise trajectory comparisons, which captures safety
24:distinctions often missed by scalar rewards. We evaluate MOSAIC zero-shot across
25:three model families, Qwen2.5-7B, Qwen3-4B-Thinking, and Phi-4, and across
26:out-of-distribution benchmarks spanning harmful tasks, prompt injection, benign
27:tool use, and cross-domain privacy leakage. MOSAIC reduces harmful behavior by
28:up to 50%, increases harmful-task refusal by over 20% on injection attacks, cuts
29:privacy leakage, and preserves or improves benign task performance, demonstrating
30:robust generalization across models, domains, and agentic settings.

315:TRAINING DATA: AGENT-SAFETYBENCH
316:We train agentic policies on the Agent-SafetyBench dataset (Zhang et al., 2024), which is designed to
317:elicit safety-critical decision-making in tool-using agents. The benchmark contains explicitly harmful
318:tasks, benign tasks, and tasks that admit both safe and unsafe execution strategies, enabling models to
319:learn calibrated, context-dependent behavior rather than relying on surface cues or task labels.
320:Task Structure and Attack Surfaces. Agent Safety Bench (Zhang et al., 2024) comprises 349
321:interaction environments and approximately 2,000 task instances spanning 8 safety risk categories
322:and 10 common agent failure modes. Tasks include both single- and multi-step interactions, with and
323:without tool use, and explicitly model realistic attack surfaces via prompt injection. These include
324:direct injections embedded in the user prompt and indirect injections introduced through adversarial
325:tool responses or environment state (see Appendix B.2 for more details).
326:Execution-Aware Supervision. A key feature of the dataset is that task correctness depends on
327:how the agent executes intermediate steps—interpreting tool outputs, assessing risk, and deciding
328:whether to act or refuse—rather than on task completion alone. This structure supports supervision
329:over execution quality instead of outcome-only.
330:Pairwise Safety Preferences. Training supervision is provided via an LLM-as-judge framework
331:(Section 2.2.1). Rather than assigning absolute safety labels, we derive pairwise preferences by
332:comparing two trajectories for the same task and selecting the safer outcome. These pairwise
333:judgments serve as reinforcement learning signals, enabling data-efficient optimization without
334:step-level annotations or ground-truth safety labels.

809:CONCLUSION
810:We show that agentic safety requires explicit control over when models act, verify, or abstain, espe-
811:cially in multi-step tool use where failures are sequential and irreversible. MOSAIC demonstrates that
812:making safety reasoning and refusal first-class, learnable decisions leads to consistent improvements
813:across model families, task types, and domains, including out-of-distribution privacy settings. Our
814:results suggest that agentic alignment is not primarily a function of scale, but of structured inference
815:and training signals that reflect temporal safety decisions. More broadly, MOSAIC points toward
816:a principled path for building reliable agents by integrating modular reasoning, preference-based
817:learning, and explicit abstention into the agent’s core decision loop rather than treating safety as an
818:external filter.

14:Abstract
15:Training tool-calling agents requires large-scale trajectory data with verifiable la-
16:bels, yet existing approaches either synthesize environments that diverge from real
17:API behavior or generate tasks without ground-truth outcomes for verification. We
18:present FIREFLY, a pipeline for generating verified tool-call data from real-world
19:MCP servers. Our key insight is to invert the standard synthesis pipeline: rather
20:than generating tasks and hoping they are solvable, we first let a strong LLM ex-
21:plore real APIs along graph-guided DAG structures, then synthesize tasks back-
22:ward from observed outcomes, guaranteeing label correctness by construction. To
23:handle the scale of real-world tool spaces (∼1,000 tools), we build a pairwise
24:tool graph and sample sub-DAGs to focus exploration on semantically coherent
25:workflows. To address environment drift in live APIs, we construct a retrieval-
26:augmented simulator that caches all exploration results and replays them dur-
27:ing training and evaluation, enabling reproducible RL without live server access.
28:Applying this pipeline yields 5,144 verified tasks spanning 240 servers and 993
29:tools. A 4B-parameter model trained with GRPO on FIREFLY matches Claude
30:Sonnet 4.6 on our held-out test set and shows improvements on multiple tool-
31:calling benchmarks including Tau2-Bench, MCPMark, and MCP-Atlas. Code
32:is available at https://github.com/leoleoasd/firefly-neurips-2026/,
33:and data and model are available at http://firefly.hailab.io/.

35:Introduction
36:Tool-calling agents interact with external APIs to complete user intents, and they have become a
37:central paradigm for building AI systems that can act in real environments [19, 33, 2, 25]. However,
38:training such agents requires many tasks with correct intermediate tool calls and verifiable final
39:outcomes. Even data-efficient reinforcement learning recipes consume thousands of such tasks,
40:for example 2.4k training samples for a search agent [10], whereas recent agent benchmarks each
41:offer only tens to hundreds, such as 50 to 115 tasks per domain in Tau2-Bench [2], 127 tasks in
42:MCPMark [28], and 500 public tasks in MCP-Atlas [1]. Human annotation could close this gap,
43:but it is expensive, domain-specific, and difficult to scale to the long tail of real APIs [33, 14, 4, 6,
44:5]. Synthetic pipelines scale more easily, although each existing design gives up either realism or
45:verifiability. When they rely on purely simulated environments, an LLM invents tool responses that
46:often diverge from real API behavior [9]. When they instead generate a user task first and then ask
47:an LLM to produce a trajectory over real tools [21, 16, 31], the trajectory may be infeasible and the

269:Our pipeline constructs verifiable tool-use data in three phases: server collection (Sec. 3.1), task

274:Scraping
275:We collect MCP servers from the Smithery registry4 using broad listing queries, prefix enumeration,
276:and domain-specific keyword searches. After deduplication and metadata fetching (tool definitions,
277:input schemas, connection configurations), we obtain approximately 3,000 unique servers, of which

280:Filtering
281:Many scraped servers are unsuitable for verified data construction. We screen each server against
282:four criteria using an LLM evaluator: Statelessness (no session memory or cross-call state), No
283:user authentication (no OAuth, credentials, or user-owned keys), Schema clarity (explicit JSON
284:typing and parameter descriptions), and Non-triviality (no echo or diagnostic-only tools). A server
285:must meet all four. We spot-check a subset for alignment. 240 servers with 993 tools remain.
